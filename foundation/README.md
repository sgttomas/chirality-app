## Standing carried with the files

("Warrant Status"): every chapter is agent-drafted under the owner's
direction; the set stands at CITED/REVIEWED and has not been AUTHENTICATED;
under K-CLAIM-1 it "binds nothing and is not a governance surface"; on any
disagreement the governed record governs. The dated revision notes in that
README identify which passages are the agent's prose and which record the
owner's words. Carrying the files into v4 does not change that standing, and
it does not adopt the historical implementation choices the thesis describes
(OD-07, OD-10).

## Notes for a v4 reader

- **Paths named in the text are Root paths at the source revision.**
  Mentions such as `docs/TYPES.md`, `docs/CONTRACT.md`, `AGENTS.md` or
  `plans/...` refer to the repository root of `sgttomas/chirality`, not to
  anything under `projects/chirality-app-v4/`. If v4 later has documents with
  the same file names, those are different documents.
- **One relative link leaves the directory.** `SE_Design_Analysis.md` line 3
  links `../AGENTS.md`. The file was moved into `docs/thesis/` on
  2026-08-02 (thesis README, relocation note); from there the link resolves
  to `docs/AGENTS.md`, which does not exist, and from the v4 location it
  resolves to `foundation/AGENTS.md`, which does not exist either. The text
  intends the Root `AGENTS.md` index. The link is left as it is.
- **The implementation the thesis describes is the v1 application**
  (Chapter 8 §8.4: Next.js/Electron desktop app). Later App generations are
  not described in the thesis.
- **Terms and mechanisms.** The thesis names mechanisms (Agent 0/1/2
  hierarchy, R1–R17 / I1–I10 / K-* invariant layers, write-scope headers)
  alongside purpose-level commitments. The conceptual working surface keeps
  a separate account of which of these the v4 basis draws on and why.
