# Model Capability Doctrine

> **Status: RATIFIED IF AND ONLY IF D-GOV-17 M1 IS RULED APPROVED.** Before
> that owner ruling, these exact bytes are an inactive proposal and have no
> operational or normative effect. On an M1-A or M1-B ruling, these bytes are
> placed verbatim in the ruled home; this conditional status line is replaced
> only as the ruled implementation directs.

## 1. Principle: capability assigns work, never authority

Runtime work is assigned to models by capability tier, not by model name.
Authority is indexed to accountability alone: no capability tier, model
improvement, benchmark result, or observed performance unlocks any approval,
ruling, issuance, gate crossing, or other act reserved to humans under
K-AUTH-1. A more capable model receives harder work; it never receives more
authority. Where this doctrine and any capability-based argument for expanded
agent authority conflict, this doctrine governs.

## 2. Tier assignment

Use the session's available models by capability tier:

- **Standard-capability agents** for discovery, research, summaries, running
  deterministic checks, and breadth verification.
- **Highest-capability agents** (at high reasoning effort where the harness
  supports it) for planning, for adversarial verification of anything that
  will be recorded as fact, and for execution that touches governed
  artifacts, fences, or rulings.
- **Reduced effort** only for mechanical execution of fully specified
  changes.

## 3. Attribution

Record which model actually ran each dispatched role in the governed run
record for the tranche, and point to that record from the corresponding
handoff-ledger entry. When no governed run record exists, the ledger entry
carries the minimum model attribution directly. Attribution is part of the
evidence chain: work whose executing model cannot be reconstructed from the
record is unattributed work.

## 4. No silent substitution

A capability-tier change within a dispatched wave is a recordable event.
Never substitute silently mid-wave; record the change and its reason where
the wave's execution is recorded.

## 5. Override

A per-run human steer may override tier assignment for that run. Overrides
assign work; they never expand agent authority and never waive attribution.

## 6. Project binding

Each adopting project binds this doctrine by citation in its project agent
index. A project-local binding may narrow the doctrine — requiring a higher
tier or stronger attribution for named work classes — and may add
project-specific work-class examples. A local binding never widens agent
authority, never weakens attribution, and never reintroduces named-model
conventions. On any conflict between a local binding and this doctrine, this
doctrine governs and the conflict is surfaced.
