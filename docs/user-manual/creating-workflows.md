# Create and improve a workflow

Start from a task you understand. A useful workflow explains how to achieve a
result and how to examine it. It should be usable by an agent that was not in
the conversation where you developed it.

## Draft the method

Ask the agent to identify the repeatable parts of work you have completed.
Separate those instructions from facts that belong only to the current project.
Specify:

- When to use the method and when another approach is needed.
- Inputs, their required condition and how to handle missing information.
- Actions, decisions and checks, including who must make a decision.
- Expected outputs and where they should be put.
- What to retain if work stops and how to resume.

Keep the instructions as short as the task permits. Do not require extra
records that nobody needs to use or examine.

The development App can create a draft from inspected or selected content in
an open library. Give the draft a clear name. Its draft list shows the available
content and actions. A draft is editable work; it is not yet a registered
workflow revision.

## Try the draft

Use sample inputs that are safe to change. Include an ordinary case and a case
with a consequential missing or changed input.

The draft list offers **Try with the authoring agent** when available, and
**Try in a fresh conversation**. The first keeps the context of the authoring
conversation. A fresh conversation helps expose instructions that depend on
unstated context. It is optional.

Either action prepares a trial message. Read it and choose the intended model,
inputs and working location before sending. Preparing the message sends nothing.
A trial exercises the draft; it does not register the workflow or approve its
results.

Inspect the outputs and the trial's reported limits. After the turn ends,
**Bring trial back** can return feedback to a chosen conversation. Make sure it
is the conversation you intend. Explain what failed and revise the instructions.
Repeat the affected case when a change needs checking.

## Review and register

Choose **Review for registration…** for the draft you want to keep. Read the
workflow text, included files, target library, findings and revision changes.
Resolve problems that affect its intended use.

Registration is a separate confirmation. Read the confirmation and complete it
only if it matches the content and action you intend. Opening a review is not
registration. Check the result reported by the App before selecting the revision
for work.

## Revise an existing method

Use the App's refinement action to make a draft from a registered revision.
Explain why the method needs to change. Test the affected behavior, review the
new draft and register it separately when ready.

Keep distinct questions separate: whether the instructions are useful, whether
the agent followed them in a particular run, and whether the resulting work is
suitable for its intended use. One successful trial does not settle all three.
