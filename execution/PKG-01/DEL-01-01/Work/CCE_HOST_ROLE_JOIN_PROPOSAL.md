# CCE Host/role original-emission join — proposed owning interface

PROPOSED source addendum only. Basis main2254d6b2806158211411aa05f74001465ce829b4 includes reviewed CCE-A2 and Host/role assessment (#1176). It changes no accepted Host/REC/role/RS contract, code or tool registry. Owner decisions C3-OD-01/02 select ordinary Codex graph work with App observation and recoverable-current-status R2 as design/proof target. This interface concerns answer and separate manager-review evidence only: no W1 insert, W2 writer, grant, R2 journal, PM05 completion, capacity migration or held Stop/Route-B work.

## 1. Authority and proof claim

Host owns original request/write/response and admitted notifications. Role owner owns actual App thread admission and frozen guidance binding. C3 owns exact base/question/answer selection and semantic validation. A mint states: the App observed one qualifying native final message and successful terminal turn attributable to its exact submitted request and role-supply source, at a named receipt cut. It does not prove cognitive authorship, instruction adoption/performance, truth, exclusivity against unobserved external supplier activity, human identity, acceptance or file work. Native history is corroboration only; role JSON, source JSON and cold records are never mint inputs.

Existing SourceRequest/SourceEvidence, turn_start_prepared_finish and RoleBinding are patterns, not this combined interface. SourceRequest identity checks alone do not require complete write/currentness. RoleBinding.observe accepts caller Values; its private fields alone do not authenticate transport. Existing execution_custody is pointer-only and ignores items after terminal; it is not repurposed as a payload/conflict index. Preserve full notification and request-response duties regardless of CCE eligibility.

## 2. Minimal private types and operations

Proposed crate-private types have no public constructor, Deserialize, generic JSON conversion or Clone of live authority:

- RoleSourceLease: borrowed original role-owner entry plus immutable binding revision, home/thread, supply reference, guidance identity and actual admitted thread-start SourceRequest chain. Role owner mints only from successful actual App admission; validates original Host write/result, not merely RoleBinding.evidence(). Legitimate inherited role requires its original admitted fork/resume continuity, not carried history text.
- ContributionIntent: C3-private immutable base raw-byte reference/hash/size, question and exact claim IDs, answer/review kind, request text bytes and producer identity. Review includes the previously minted selected answer exact bytes/hash and original observation standing. No grant or target-write input.
- ContributionDispatch: opaque Host instance, capture epoch, H5, thread, original SourceRequest reference and role-source pin. It owns no second transcript.
- ContributionMint: immutable selected emission proof plus guarded access to exact selected text; current recheck and historical observation are distinct. A historical DTO cannot restore it.

Operations: prepare_intent (C3); admit_role_source (role owner); begin_contribution_text (Host sender); inspect_capture (bounded observation, no mint); mint_contribution (joint source recheck); with_current_contribution (guarded consume/freeze); retire_capture. Names are design labels, not available APIs. No generic callback receives locks or arbitrary mutable Host access; guarded consume is a closed internal operation that seals the selected immutable CCE payload/revision without filesystem/network work.

Answer requires TASK role. Review requires a separate HELP_HUMAN/WORKING_ITEMS conversation and distinct request/turn/item; home/generation need not differ. Exact source bindings establish separation; labels alone do not. Pending run-end notice or other wrapper composition must be resolved by its owner before constructing the exact one-text intent: neither silently prepend bytes nor bypass that existing duty. Unresolved composition refuses CCE admission, not ordinary user work.

## 3. Dispatch cut and early events

Reserve one CCE capture before request registration/writing. The source sender retains exact single-text turn/start frame and original requestRef/ID. Immediately before write, under the existing source admission gate and Inner, record receipt_position as dispatch_cut and bind original pipe identity/epoch; record this alongside actual write-attempt admission. Send positions and receipt positions are different domains and never compared. Release source locks for actual write exactly as existing sender does. Complete-write proof is set only by actual successful write completion, even when response/events already arrived.

Capture hooks run only on admitted current-generation frames inside on_line's existing Inner serialization. They do not filter/drop frames or answer supplier requests. Before the correlated response supplies turn ID, capture at most one candidate turn for the selected thread after dispatch_cut, one final item and one terminal fact. A second distinct candidate turn poisons this capture rather than growing a history search; unrelated threads/generations are ignored for eligibility but retain ordinary handling. This conservative refusal affects CCE evidence only, never another turn's execution. Response supplies the exact expected turn and must match the buffered candidate. No later history scan repairs overflow/ambiguity.

Item/terminal can precede response and write completion. Mint awaits all facts: exact original request, complete write, one valid correlated successful TurnStartResponse, one actual item/completed agentMessage with explicit final_answer phase, and successful turn/completed with no error/contradiction. All notification receipt positions exceed dispatch_cut in that same generation. Response.turn.items is not an item-completed witness. Missing/null phase stays unknown (the generated supplier schema permits it); commentary/delta/failed/interrupted turns cannot mint.

## 4. Duplicate and conflict semantics

The hook also sees responses that general Host processing calls uncorrelated after its first settlement. Exact repeated facts at the same native identity are idempotent; new receipt positions do not create a new emission. Compare named parsed-frame identity plus relevant tuple/content, not text hash alone. A second final item ID is ambiguity even with identical text. Same item ID with changed text/phase, response turn disagreement, malformed envelope, conflicting terminal status/error, or an observed competing same-thread injection/steer that prevents original-request attribution poisons the capture. Do not claim this detects unobserved external activity or proves model-internal provenance.

Keep first qualifying fact and one bounded conflict reason/identity; do not accumulate all conflicting payloads. Different delivery timestamps in otherwise repeated facts require an explicitly reviewed equality rule; default to conflict unless the supplier field's repetition semantics are established. No newest-wins replacement. Late admitted contradiction after mint invalidates future current rechecks; the original mint remains a historical observation at its earlier cut with the later limit attached where representable. Freeze is a point-in-time claim, not a promise of no future frame. Source loss changes currentness; it does not retroactively fabricate or erase a minted observation.

## 5. Mint, closure and guarded recheck

Mint validates original Host object identity; H5/home/thread; request frame/requestRef/ID; source pipe binding; actual complete write with no error/in-progress/limit; correlated response and event positions; role entry/revision and admitted origin; exact C3 intent/selection revision. It requires current ready/unclosed source and unpoisoned capture. It records the receipt frontier and capture revision atomically. A terminal turn is not a closed Host generation.

Before mint: source closure/refusal/replacement, role origin unavailable, cancellation or stale intent refuses new mint. Closed-generation-frame history cannot advance capture. After mint: source closure may preserve selected exact answer or review for historical recording under CCE-A2; it cannot dispatch a new stage or restore currentness. Each contribution retains its own current/historical status. A fresh manager request may review a historical answer only through new actual admission and exact content binding. Explicit cancellation retires the capture epoch; late return cannot revive it. Cold read may resolve recorded byte references only; no live request, role, authorship or grant is rehydrated. R2 persistence remains separately designed.

Proposed lock order for adopting owners to verify against actual call graph: CCE working-set mutex → role-owner mutex/read lease → Host attachment/source gate → Host Inner. Map/home lookup occurs before this chain and releases its lock. No Host on_line/closure path acquires CCE or role locks; it updates only Inner/capture revision. No reverse edge may be introduced. Parsing, source filesystem resolution, supplier writes and persistence occur outside this chain. Reacquire chain and compare all revisions before mint/freeze. Existing role mutation need not acquire CCE lock: its own held mutex/revision supplies exclusion through consume. Existing closure remains serialized by Inner. Neither a public boolean check nor an unprotected sequence of independently valid snapshots is sufficient.

Capability text access uses a bounded read/transform outside live locks followed by exact digest/revision recheck; final consume is in-memory only. Do not hold Host locks while awaiting a turn or call consumer-controlled code under them. If actual existing lock graph cannot accommodate this order, return that precise cycle before implementation; this source proposal is not a proof that the lock migration has occurred.

## 6. Bounded capture and borrowing

One active CCE set shares the existing one-payload 1MiB CAM envelope. It holds at most two completed contribution proofs (answer and distinct review), with only one active request capture at a time. No second full payload, hidden account reservation or lifetime slot before successful freeze; existing64-identity rule unchanged. Candidate early-turn/item/terminal metadata is fixed-cardinality. Over-budget input, metadata, text, JSON escaping or final serialization refuses advancement before identity exposure; no truncation into a false exact-content claim.

Original Host request/response/journal custody remains its existing owner. CCE borrows exact selected entries through source-owned handles; it never calls observe()/evidence() to clone full history as authority. Proposed immutable reference storage for selected text must preserve existing original bytes and release capture-owned references on retirement. Preflight byte length before any selected-content clone; account for simultaneously retained raw text, parsed semantic value, escaped final bytes and proof metadata in the common budget. If staging requires two full buffers, count both or use ownership transfer—do not wave it away as borrowing. Existing Host unbounded read_until/journal behavior is not claimed fixed by this interface; no global memory bound is asserted.

Authored identity is exact decoded UTF-8 text bytes, including whitespace. C3 parser requires one complete JSON value, rejects duplicate keys/fences/trailing text and unsupported references. Parsed source-frame identity is explicitly a named Host serialization method, not wire bytes; source owner must freeze method/version before adoption. Final positive review representation gap in A2 remains separate: genuine emission does not license an invented enum or integration plan.
