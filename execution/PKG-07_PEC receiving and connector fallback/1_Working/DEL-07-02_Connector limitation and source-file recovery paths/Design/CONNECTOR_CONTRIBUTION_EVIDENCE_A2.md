# CCE-A2 — answer/review custody and historical stage closure

PROPOSED named source amendment for C3-R2-S. Not reviewed, adopted, or released
for implementation. Basis: fc92dd1591 (merged PR #1172). WORKING_ITEMS prepares
this bounded DEL-07-02 proposal; it does not amend ACT, Host, role or RS owners'
accepted contracts or supply their concurrence. CCE-v0.1 and R1 remain pinned
historical proposals; formats 0.1–0.4 and proposed 0.5/message0.1 bytes are unchanged.

## 1. Independent result and scope

Refine selected lifecycle A for one exact format0.4 question/account, one selected
answer and one separate manager review. The result is source-bound historical
contribution recording with integration outstanding, not a substitute graph
write. Rules here remain applicable if graph integration stays held or W1 is
later selected. S/T/W, A5/A12 allocation, R2 journal and CAM retirement remain
unselected. No graph target, plan, scope capability or human act is minted here.
A future writer consumes these contributions only under its separately reviewed
source; an answer or manager disposition never releases it.

The base is original exact serialized bytes, not a reserialization: resolve the
same opened project, canonical CRP path, account ID, byte length and SHA-256;
apply existing 0.4 schema AND semantic validation. Preserve question, claim,
fact, comparison, contradiction and gap identities. Changing bytes at the same
locator/ID invalidates live preparation; do not follow a new latest account.
Unresolvable current base prevents new preparation. A retained historical base
binding may describe a previously observed subject, never current resolution.

## 2. Authorship eligibility is an original-source join

The proposed join is owned by Host/role sources, not by C3 renderer inputs. It
must retain an original App-submitted single-text turn/start SourceRequest,
complete-write standing, correlated successful native result, full App-session/
home/spawn generation, thread and turn; original role-supply RoleBinding for
that home/thread; one final-answer agentMessage completion and successful
terminal turn. TASK supplies the answer; a distinct HELP_HUMAN/WORKING_ITEMS
conversation, request, turn and item supplies its review. Role guidance proves
supply only, not adoption, truth, cognition, human identity or authority.

Bind the exact request text to the frozen base and question, contribution kind,
and (for review) the exact selected answer bytes/hash and claim IDs. A request
that merely mentions another hash in free prose is not the reviewed structured
request producer. This producer remains a proposed interface. The result must
belong to that original request, never a history selection made afterward.

Use decoded message UTF-8 for authored byte length/hash; retain original exact
text, including whitespace. Parse one complete JSON value, reject duplicate
keys, fences/trailing text and unsupported references. Hash parsed source frames
only under the existing named host serialization method, never call it wire
identity. Event receipt positions are scoped to their generation. Item and
terminal can precede the request response; each must follow the original
dispatch and the join must await all mutually consistent facts. Ordering in
unrelated streams is not compared numerically. A review dispatch depends on the
completed selected answer, not merely on equal text discovered later.

A second distinct final item is an ambiguity even if its text is identical.
Conflicting repeats at an identity/position refuse; duplicate delivery must be
handled by the original Host owner, never converted into a second authorship
claim by C3. Interrupt/failure, missing phase, source loss before mint, missing
complete-write proof, wrong home/thread/turn, imported/fork/injected history and
public JSON copies cannot mint. Closed-generation late frames remain historical
observations or gaps; they cannot complete a fresh mint. Exact role and original
request sources must still be available at mint and final currentness recheck.

Existing SourceRequest, SourceEvidence, RoleBinding and journal primitives do
not themselves implement this combined capability. Define and review its
non-deserializable mint/recheck and bounded capture interface with Host/role
owners before code. Schema/definition tests cannot prove actual emission.

## 3. Stage closure and what may still be recorded

Stage labels below describe proposed lifecycle distinctions, not new accepted
schema values or a second registry. Operations serialize against one active
working set; renderer revisions cannot choose the winner of racing completion,
cancellation, replacement or freeze. Source owner and registry must expose a
reviewed linearization point before implementation.

| State/event | Required result |
|---|---|
| Base admitted, no answer mint | May prepare a bounded answer request; no authored answer or contribution account yet. |
| Answer request in flight; generation closes before mint | Refuse new mint; retain gap/actual request outcome as available, no invented answer. Existing0.5 requires an answer, so do not fabricate a0.5 record. |
| Answer genuinely minted; source later closes | Retain exact answer and mark historical at recording; do not rehydrate a current capability from receipt JSON. Answer-only final recording may be prepared subject to exact base/size/registry rules. |
| Manager review requested on the exact minted answer; review source closes before mint | Answer remains historical/current as actually warranted; review remains unavailable, never completed from late/history output. |
| Both contributions minted; either original source closes | Preserve each contribution's own current/historical standing and limits; a still-current review cannot make its answer current. Historical recording is permitted, new authority is not. |
| Changed base, answer, cited identity or selected review | Dependent preparation is stale. Keep previously captured content historically where bounded; no automatic rebind or replacement. |
| Explicit cancellation before graph dispatch/final freeze | Discard transient working set under lifecycle A, retaining no invented durable completion. This does not retract emitted supplier messages or promise turn rollback. Late returns cannot resurrect the set. |
| Source closure without cancellation | Does not implicitly cancel or discard already minted contributions. No new stage is dispatched from the closed source. |
| Final freeze | Revalidate selected bindings, semantic content and exact serialized bounds; transfer the one payload into existing CAM registry, consuming one of64 only at successful freeze. No second payload/identity or hidden reservation. |
| Cancellation after final freeze | Existing CAM/CRP semantics govern retained consumed identity and any started publication. No new lifecycle shortcut, unlink, retry or token revival. |
| Process exit before freeze | Transient set and original capabilities are lost. Missing durable record does not mean no request/output or write occurred. PM05 limitation remains. |
| Cold read after publication | Recompute current resolution of exact references; report recorded/matching/changed/missing/conflicting separately. Never reconstruct live authorship, role or authority from files. |

Answer-source closure alone does not establish that a new manager source is
admitted or authorize automatic continuation. A later independent review may
only be proposed through fresh actual App submission and fresh manager-role
custody, explicitly reviewing the historical exact answer. This proposal does
not release that producer; its owner must specify how historical answer content
is supplied while retaining the original observation's standing. No original
answer mint is recreated. This distinction avoids treating all sources as one
boolean current flag, while not silently approving a continuation mechanism.

If a future separately selected writer has begun, CCE-R1's original-attempt
retention and no replacement/no rollback rules take precedence; this source-only
slice must never erase such state. It creates no graph dispatch path itself.

## 4. Content review, disposition and representation limits

Answer claims require exact base support IDs and complete carried gap pointers/
contradiction IDs. Citation presence and a valid JSON value are not entailment
or substantive quality. A manager reviews the exact emitted answer, covers its
claims and preserves limitations. A changed answer, even whitespace-only, needs
new exact binding; no newest-review winner. Conflicting reviews cannot be
silently overwritten. One working set is not permission for an unbounded review
history cache; if required conflict evidence cannot fit, refuse advancement and
return for scoped treatment, never truncate to make a successful account.

Existing message0.1 permits changes_requested, cannot_assess and
reviewed_for_integration. Nonintegration dispositions have plan_sha256=null;
reviewed_for_integration requires an actual bound plan. This slice has no plan
producer. It can specify truthful changes_requested/cannot_assess observations,
not invent a positive integration disposition. Do not use cannot_assess merely
as a storage workaround when the manager actually completed a positive content
review. A neutral positive-content-review disposition is a **representation gap**
requiring a named additive schema/consumer proposal and independent selection;
this amendment does not change schema enums or silently reinterpret old records.
The underlying genuine emission can be an observed but unrepresentable outcome,
not discarded or falsely promoted into a supported final account.

An answer-only account has review/integration/plan absent and an explicit gap.
A representable nonintegration review keeps integration/plan absent and explains
why integration is outstanding, independently of content quality. Missing
manager review is not acceptance. Manager review is not a person's A4/A5/A6/A7,
not professional reliance, and not permission or a performed-duty badge.

## 5. Capacity and references

One active set shares CAM-R1's one full payload/1MiB budget; an existing prepared
or in-flight account excludes CCE and vice versa. Host-owned original evidence
may be borrowed only under an explicit bounded ownership/capture design; this
is not a license to duplicate full transcript/history pages. Exact authored
UTF-8, JSON escaping, metadata and final serialized bytes count toward the bound.
If the selected artifacts exceed it, refuse before identity exposure; do not
summarize authored text into a false exact-content claim. Allocation/ownership
proof and post-start outcome retention are implementation checks still required.
64 lifetime identities, consumed tombstones, no eviction/reset and one-use
publication remain unchanged. R2 journal/current-status retention is not adopted.

Use RS§9 kinds, claimed identity, named methods and resolution at write/read;
keep recorder, emitted role and human actor distinct. Do not mint typed R3/R4/R7
runs or human-act records. Existing scoped RS concurrence supports these
principles only; it does not concur on this exact amendment or implement Host
minting. Exact new interface adoption requires its owners' review.
