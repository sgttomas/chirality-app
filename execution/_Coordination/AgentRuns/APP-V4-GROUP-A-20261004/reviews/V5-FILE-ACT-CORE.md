## Findings

### F1 — Blocking / P1: definite first capture failure is promoted to record-pending and later counted

Location: `src-tauri/src/act_control_file.rs:258–277`, especially admission at 260–275; first-lock failure at `:296–303`; continuation at `:306`. The written test `file_act_capture_lock_failure_retains_original_once_and_retries_in_order` explicitly fixes this behavior as its expected result.

Trigger: `.chirality/captures/.capture.lock` is a directory (the proposed fixture), or capture publication definitely fails before any capture was stored. The code has already set Captured, assigned captureId and inserted the original into native_captures. The lock failure returns **AC-8 record pending**, not a capture failure. A later continue/recover flush publishes that in-memory object and appends an act/decline with the original time, without a new native confirmation.

AAC §4.1 step 6 (APP_ACT_CONTROL.md:167) explicitly says when the capture store cannot be written: “nothing captured”, the person is told, and “nothing counts”. Step 7 and AX-13 reserve record-pending for a kept capture followed by a failed record write. The later AAC §5.2a and RS §14.1a permit retry of an **actual/originally admitted capture** and prohibit append before durable capture publication; AAC also correctly distinguishes uncertain publication from definite absence. Those provisions do not explicitly resolve whether a definitely failed first capture may become an admitted capture merely because its native input was retained. The new API and test silently choose that interpretation. Parent confirmed in the review exchange that no later A4/A6/A7 amendment was supplied and bounded code authorization did not widen this rule.

This is a source/contract conflict, not an assertion that native origin was fabricated: the opaque native event really is retained in process, and the shared writer still publishes capture before record. The defect is treating that event as an already captured, record-pending act after a definite first capture failure. Do not discard genuine uncertain-publication evidence or reopen the separately reviewed A15 implementation on this finding alone. Repair A4/A6/A7 to the accepted capture-failure state/continuation boundary, distinguishing definite absence from uncertain publication; alternatively obtain a named reviewed source disposition reconciling these clauses before accepting this API. Add the inverse check: a definite first capture failure cannot later become an act solely through generic retry. Keep post-capture record failures retryable without recapture.

### F2 — Blocking / P2: regular-file rejection occurs after an indefinitely blocking open

Location: `src-tauri/src/act_control_file.rs:90–100`.

Trigger: the selected contained path is a FIFO with no writer, or an ordinary selected file is replaced with a FIFO before the pre-presentation or post-confirmation reread. `check_path` rejects symlinks only; canonicalization accepts a FIFO. `OpenOptions::read(true).custom_flags(O_NOFOLLOW).open(path)` blocks on that FIFO **before** the `before.is_file()` rejection is reached. Thus compose or the owning native continuation can hang indefinitely while retaining the ActControl ownership required by ROOT_API, instead of refusing a non-regular subject. This is established by the source sequence and POSIX FIFO open behavior; no reproduction was executed under the no-test brief.

Reject non-regular named metadata before opening and make the actual open resistant to replacement with a FIFO (for example nonblocking descriptor open plus fstat regular-file validation). A pre-open check alone leaves the replacement race. Add bounded timeout-controlled FIFO tests for initial composition and replacement before capture; do not let the test itself hang the lane. Preserve the existing symlink/content-stamp checks.
