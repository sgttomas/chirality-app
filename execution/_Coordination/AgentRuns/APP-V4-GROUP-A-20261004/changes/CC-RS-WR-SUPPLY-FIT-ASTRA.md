## Decision and exact candidate

Choose optional `nativeTurn` with an exclusive alternative to integer `turn`
for workflow R3 only, plus faithful `incomparable`. The existing integer field
and historical records are unchanged. Both coordinates in one workflow body
are rejected: their correspondence is not established and not needed. A
supplier reference alone is insufficient because existing R3 requires a turn;
opaque native identity is actually supplied whereas an ordinal map is absent.
Changing integer turn to a union would overload its namespace and affect
existing readers. Adding a global turn map or broadening model_turn/EXEC would
create unrelated scope. The chosen alternative is the smallest truthful join.

Exact private source copies, unified patch and fixtures are in
`proposed-rs-supply/`. The patch changes only RS Design/schema. New examples
are private proposed additions, not modified historical examples. RS-v0.10
and container 0.1 stay unchanged, with this named change and schema fingerprint
identifying the technical revision, consistent with prior in-place 0.1
changes. Old strict readers reject the added enum/field and report incomplete
record; do not claim forward compatibility or strip them. Propagate the exact
reviewed Design schema to bundled schema and validation/receiving/display
consumers before emission. If independently deployed consumers need negotiated
versions, that is a separately assessed compatibility requirement, not hidden
by this in-place revision.

The native branch requires nonempty thread/nativeTurn, check reference and
explicit unknown adoption. New native receiver must resolve both immutable WR
references, verify owning run/conversation/purpose/text method+value and exact
check.turn, and copy state exactly. Schema validation alone establishes none
of those joins or native provenance. Missing queried turn leaves WR evidence
available but R3 pending/unavailable. A not-found/unreadable read with a known
queried turn retains that source coordinate. Never invent turn 1, count partial
pages, convert a UUID, or infer equality from matching digest characters.

immutable publication and resolver; Root integrates prepare/publish/send and
native source joins; RS reader/display owners preserve limitations; EXEC owns
lifecycle separately. Existing Group A WR/RS/EXEC/Root join only: no deliverable,
DAG or group-order change. Downstream contract notices/adoption remain parent

  incomparable; adoption always unknown. Start and end-notice both covered.
- Source-resolved joins reject wrong record kind, run, conversation, purpose,
  text identity method/value, native turn or cross-project reference. Failed
  resolution preserves observation plus explicit limit, never verified uptake.

  both coordinates, empty native turn, missing check/thread and inferred adoption

- Two reads publish two immutable checks/R3 observations. A pending retry keeps
  original identity/read time; check or R3 write failure after send never resends.
- Cold owning-project resolver finds the original supplier objects; missing,
  conflicting or corrupted object reports reference limits. Prepare/publication
  failure prevents send under SC-1; no false durable-record claim.
