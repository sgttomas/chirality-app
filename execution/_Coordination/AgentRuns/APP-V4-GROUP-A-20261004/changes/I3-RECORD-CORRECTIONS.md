## Bounded API and actual consuming join

`decision_view::record_relations::read_logs(actual paths)` calls the existing actual read_log and retains every returned immutable record/source plus read limits. `project_from_read_claims(claims, completeLogs)` reuses the bundled schema validator and projects exact IDs, paired-reason/same-kind links, corrected-by, weak correction groups/current candidates and explicit diagnostics. It retains original/correcting/readable branch entries. Identical unchanged copies remain one identity with all sources; conflicting bodies cannot choose a map-last winner. Missing/ambiguous target is unresolved, wrong-kind correction nonconformant, self/cycles/contradictory owning-log relation refuse replacement. Chains depending on unresolved members keep current relation unresolved rather than selecting a descendant as replacement.

Validated explicit links provide recorded correction precedence; competing corrections of one target may use a complete unique owning-log sequence. Incomplete/torn streams cannot provide that sibling total order. Cross-log incomparable siblings retain every contender and ambiguity. Output IDs are sorted only for stable display, never to select a current correction; timestamps/filename/UUID supply no ordering. Provenance remains “recorded claims; no native origin or human chronology verified”. Unrelated independent claims are retained. read_log's rejected/nonread lines remain explicit limits, not fabricated valid records.

The decision_view join is only three additions: public subordinate module; project_from_read_claims on its already frozen once-read `source_claims`/`complete_logs`; returned `recordCorrections` field. It performs **no second file read** or mixing of later mutable log observations. Existing request resolution, partial-order/capture/lapse/current-content computation, native queue-specific ordering and output rows/limits/unresolvedRecords are byte-untouched. Mechanical removal of those exact additions reproduces the indexed decision_view bytes exactly; checked before freeze. This added general field concerns correction components of recorded claims, not current human act/disposition/admission and not a new professional/native warrant.
