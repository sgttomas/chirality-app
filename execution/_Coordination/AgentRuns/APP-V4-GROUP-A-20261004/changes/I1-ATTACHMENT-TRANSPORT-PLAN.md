Proposed APIs (private-backed, non-Deserialize capabilities; final names coordinated with consumer):

```rust
Host::prepare_attachment_turn(generation:&Value, thread:&str,
    expected_turn:Option<&str>, person_text:&str,
    selections:&[SelectedTextAttachment]) -> Result<PreparedAttachmentDispatch,AttachmentHold>

    &AttachmentCancellation) -> Result<SourceRequest,String>

```

prepare mints one new_submission_ref, prepares the whole ordered list, reserves a genuine never-reused RPC in current ready/full generation, and publishes/reads back complete metadata plus prepared client record. A separate source-owned cancellation capability permits cancel before committing dispatch; it is not a renderer actor/permission proof. dispatch validates this same prepared capability, current home/full tuple/known thread/live steer target and cancellation, then uses the actual source pipe. SourceRequest remains the existing receipt/wait/status interface. Failed preparation/reservation never acquires a send position. If a failure occurs after RPC reservation, retain the prepared observation/limits, consume that RPC, release transient inputs when no longer needed and send nothing. An explicit later user send creates a new token, never replays this packet.

## Prewrite barrier and observations

1. Establish approved root/separation; obtain owning publication lock. Prepare complete list and transient input snapshot; validate schemas, unique token/IDs, exact source references/order, native params and known full scope.
2. Reserve RPC under Host registration lock without sendPosition or pending/write-success; retain private source registration. Durably publish full NIR array, then exact prepared client custody; read back and resolve every reference against the same immutable list. Any partial/unreadable/sync/conflict failure sends nothing and returns its actual cause.
3. Before the commit barrier, revalidate each retained private selection against its exact source and frozen identity/input bytes using the reviewed producer read path. Content/source/missing-file drift after durability refuses without rewriting the original metadata; any discarded revalidation preparation IDs are never adopted or sent. This adds no producer edit or path substitution. Then recheck cancellation, ready/open FULL generation, known thread, live expected turn and actual source pipe immediately at the dispatch commit barrier. Persistence IO must not hold the reader's Inner mutex or suppress required supplier requests. Introduce a bounded Host dispatch gate shared with deliberate source replacement/stop: gate → Inner → source pipe, recheck then release Inner for pipe write while gate/pipe retain that source. Mutation paths must honor this gate; avoid inverse lock order/deadlock. This is a source-write coordination mechanism, not a policy veto. A generation/pipe change before commit cancels without write. Unexpected OS EOF/write failure during an attempted write remains uncertain, not retrospective no-send.
4. Only at actual attempted dispatch advance sendPosition and pending/write account. Write failure is write-failed/unknown; success sets genuine sentFrame. Persist existing permitted outcome metadata after attempt. If postwrite metadata persistence fails, expose written/uncertain durable observation plus hot raw receipt, never report no-send or resend. Cancellation after commit does not undo an attempt; interrupt remains separate native turn control.

A prepared-only client record is a time-local fact. Hot explicit cancellation/no-attempt can show not sent; cold prepared-only with unavailable later evidence MUST be unknown/unavailable dispatch, with no automatic retry. No retention/deletion/compaction is selected. Per-home configuration/policy remains inherited.

## Resolver and evidence limits

resolve_submission reads the existing custody/source records and returns original immutable association/list/full generation/RPC/method/thread, actual write/outcome observations and limits. In a hot Host it uses ONLY the genuine exact source receipt's first correlated envelope: response object/exactRPC/no method/no error, successful owning write, valid native result and thread/target consistency. For start use result.turn.id (response may omit threadId); any actually reported thread must match original bound context. For steer result.turnId must equal actual expectedTurnId. Malformed/null/error/foreign/repeated/conflicting response preserves raw native journal and unknown correlation with cause. Never latest-turn/proximity/text/thread-only/counter-only inference, and never rewrite NIR turnRef/supplyRefs to native turn ID. Distinct submissions to one turn remain distinct.

Cold client outcome metadata can preserve App-observed written/error/result facts; it cannot reconstruct a native turn from responseReceiptPosition when the native evidence stream is unavailable. Current raw journal is memory-only. Do not add a native reply/transcript cache to compensate: surface native-reference unavailable until the owning evidence stream is actually available. No hot receipt can be imported from JSON or bound to a successor Host. Existing source-reader resolver should validate source schemas/order/state independently of status booleans, and retain partial/unreadable/conflicting storage limitations.
