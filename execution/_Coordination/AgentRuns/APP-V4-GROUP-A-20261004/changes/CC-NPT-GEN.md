## Applied successor and rationale

- NPTD-v0.3 documents full H5 generation and receiving boundaries. `npt.plan-revision` advances resource `v0.1` → `v0.2`; `npt.item-anchor` advances `v0.2` → `v0.3` because revision-key grammar changes. The unchanged delegation-export resource stays v0.2. No old integer union or legacy key grammar in these successors. Historical result files and historical supplier constants stay as labelled.
- Checklist references carry the full closed tuple. Internal maps/closed sets use all three immutable values. Each receiving view binds one session/home; a different session/home uses a separate instance. Foreign/unready/closed generations and malformed metadata are refused before checklist attribution; receipt positions increase per complete tuple and may restart under the successor. Caller object/reference mutations cannot rewrite internal generation identity. Duplicate ready, active replacement before closure and wrong-generation closure refuse; a delayed repeated closure of an already closed tuple does not end the successor.
- Opaque operational key format v2 is lossless base64url of each original UTF-8 string without padding or Unicode normalization, separated by `.` (outside that alphabet), with fixed component order. Plan keys: `pi:v2:E(thread).E(turn).E(item)`. Checklist keys: `cl:v2:E(appSession).E(home).counter.E(thread).E(turn).position`. Numeric components are decimal integers with no leading zeroes. This avoids ambiguous delimiter concatenation and counter-only identity without probabilistic hashing. Original native identity/content fields remain unchanged. The operational encoding is named for independent technical review; it does not settle content canonicalization or HOSTING U-08. Shape schemas alone do not bind a derived key to component fields: `reference_identity_matches` performs the required producer/receiver semantic check.
- Native plan indexing includes `(thread, turn, item)` so reused item IDs in different turns do not alias. Plan references carry neither generation nor receipt position; the same-home live/history identity survives relaunch. Every history-read envelope explicitly carries source-home context beside the unchanged native response; receiving requires that home match its configured/ready view. Missing/foreign context or an unbound view refuses before merge. New observations of a previously not-recoverable checklist create only a new receipt sequence at ordinal 1, never restore old revisions.
- All local maintained schema examples and scenario envelopes use successor identities/context. Native fixture generation remains deterministic. The original invalid checklist example retains its original standing/item errors with a valid new tuple/key, so it still tests the intended error rather than failing incidentally on an obsolete format. Added negatives test obsolete formats separately.
