## Exact proposed terms for A, if selected

1. Add **candidate examination**, a distinct standing, without rewriting LS-5
   or LS-8 as if an unshipped candidate were a release. Extend TT-1/TX-1 and
   affected selection/run records only for this bounded route; ordinary drafts
   and arbitrary copied packages remain ineligible.
2. Authority has three separate sources: the owner's named product-contract
   decision permitting this standing; the contents integrator's reviewed
   selection of the exact closed v4 bundle set; and the examiner's explicit
   choice of a permitted examination scope. No one of these substitutes for
   another or for point-specific native/supplier/human-act authority.
3. A reviewed binding names the contract/amendment version, immutable build
   subject, manifest digest, source commit and package-relative source path,
   final package identity-record reference/digest (joined to the earlier compiled
   input selection), full workflow identity (kind, origin, source root, name, revision and method),
   complete file-set digest, and permitted examination scope. Its custody must
   be supplied by an adopted trusted build/selection mechanism, not inferred
   from a caller-provided receipt. The implementation design must establish
   that mechanism before this proposal can be implemented as admission.
4. Keep bundled origin and an explicit candidate source root. Never substitute
   a shipping-release source root. A held candidate copy, if admitted at all,
   retains that same candidate tuple and separately records its holding
   library; it is not LS-8. Require a valid vacant unregistered slot, same name
   and exact bytes. Registered, unreadable, corrupt or orphaned slots refuse
   candidate reinterpretation. Scope the first implementation to direct
   bundled selection unless held-copy coverage is expressly commissioned.
5. Resolve against the compiled build input and actual physical package;
   reverify content, authority and scope at preparation and supply. Missing or
   mixed binding, mutation, wrong name/method/revision, extra/missing files,
   false history or scope mismatch refuses before prepared records or send.
   UI and retained evidence continue to say candidate examination.
6. Candidate inventory remains separate from actual shipped history. Only an
   actual release-registration decision over the exact final release subject
   creates release standing. Preserve candidate-to-release correspondence and
   recheck the final release path; a build, smoke pass, merge or examination
   decision is not release registration. Earlier candidate evidence retains
   its original scope.

These terms are a decision-ready boundary proposal, not an adopted receipt
schema or authorization for implementation. The adopted schema and custody
mechanism require WR/PKG and affected consumer review before runnable support.
