## Recommended architecture for owner decision: one App-owned graph operation

Develop W1 as a bounded **proposed** source successor: one deterministic graph
insertion operation used by human and agent callers through the same route,
with separate actual caller/source custody and treatment. This is a material
architecture choice replacing CCE's supplier writer, not an implementation edit
or selected permission-class assignment. Supplier fileChange remains observation
only and cannot earn authorized-integration credit on this route.

Proposed private interfaces (none currently available):

- `prepare_graph_insert(subject, selection, preimage, plan)` creates a bounded
  proposal and exact preview, with no filesystem effect. Both human and agent
  entry points call it. It accepts original host-held account/answer/review and
  manager-selection sources, not renderer assertions; target and scope admission
  remain required. It returns an opaque proposal handle and inspectable bytes.
- `resolve_graph_treatment(proposal, original_caller, policy_source, scope_source)`
  uses the same operation identity/class for both callers. Default is proposal;
  agent direct application requires a genuinely admitted effective direct grant
  under a selected class decision basis. Missing/unconfirmed grant cannot open
  direct treatment. No A16 or routine tool permission promotion.
- `apply_graph_insert(proposal, admitted_execution_basis)` is the single writer.
  Human-origin execution requires its actual original interaction/custody, not
  `actor=human`. Where proposal acceptance is required, admitted A5 is separate
  from execution A2 and must bind the exact proposed item. Agent-origin execution
  requires its admitted direct treatment or legitimate accepted-proposal route.
  Both use identical scope, preimage, target, bounded insertion, byte-preservation
  and postimage/reread checks. Native confirmation is not automatically A5/A12;
  those producers must exist and be reviewed under their owning contracts.
- `observe_graph_outcome(original_attempt)` retains actual/uncertain results,
  even after invalidation, independently of capture/account publication. It
  cannot retry, roll back or reauthorize. Supplier output alone cannot call it
  with fabricated evidence or claim the actual deterministic operation occurred.

Semantic parity means one operation/precondition/effect/outcome contract, not
identical authority of all callers. A person may execute an operation through
its genuine route without an agent autonomy grant; an agent cannot impersonate
that person by selecting the same endpoint. Acceptance and execution remain
separate even if one designed UI sequence eventually performs both. Origin,
basis, undo route and later examination must be visible; undo is a new operation
under the relevant treatment, never automatic rollback of an uncertain result.

Proposed classification for explicit owner decision: effectful, may apply within
granted autonomy, conservative proposal default; never class-none merely because
it is a file edit. This would need a named DEL-04-01 addition with a decision
basis and DEL-04-02 source/control join. A12 changes autonomy settings; it is not
required for the person to apply an accepted item and is not silently demanded
for every graph maintenance action. If this classification is not selected, the
operation stays unclassified/held; code must not synthesize a default grant.

Contract cost before implementation: review the ACT operation/class treatment,
actual source-owned scope admission, A5 proposal-acceptance producer and any A12
direct-setting producer; coordinate DEL-04-02, DEL-01-04, DEL-04-03 and Host/role
custody owners; define CCE writer successor and new operation outcome reference.
Existing A16/A4/A6/A7 capture cannot fill these missing kinds. No current code
implements this complete route. Parent selection must name architecture,
classification and producer work; source independent review must cover exact
interfaces and negative cases before bounded code release. It supplies no actual
project target authorization or performed human act.
