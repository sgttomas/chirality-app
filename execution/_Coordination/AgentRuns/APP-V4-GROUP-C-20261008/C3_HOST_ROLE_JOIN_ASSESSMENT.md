## Smallest proposed private interface

Names below are illustrative, not registered tools or adopted APIs. Keep C3 semantics (base/question/selected-answer/strict authored JSON) with its owner; keep wire/source admission and capture with Host, role origin with the role owner. One answer slot and a later review slot belong to the already selected bounded CCE working set; not a global contribution registry.

1. **Structured request binding.** C3 source owner prepares an immutable exact text from base raw-byte locator/ID/hash/size, question/claim IDs, kind, and for review the exact already-selected answer bytes/hash. Its private request input proves the producer selection only, not authority. The App composition owner supplies the original admitted role source for exact home/thread: TASK for answer, HELP_HUMAN or WORKING_ITEMS for review. Require distinct thread/request/turn/item and original supply association; do not require different homes or generations unnecessarily. Existing thread-start provenance must be checked against actual Host private evidence, not reconstructed from RoleBinding.evidence(). An already admitted inherited-role thread requires the role owner's actual fork/resume chain; history alone is never substituted.

2. **Host begin/capture.** A private `begin_contribution_text`-style method validates role/request association and budget, reserves one capture BEFORE dispatch, then calls the existing scoped native sender. It returns an opaque non-Serde dispatch handle referencing original SourceRequest and capture identity. At the final prewrite source gate record the current generation receipt cut for this dispatch; do not compare sendPosition with receiptPosition. Register the capture before allowing write/reader races. Keep only bounded candidate metadata until response supplies turn ID. Early item/terminal frames after the cut may be retained by exact thread/turn under an explicit small ambiguity/budget policy; unrelated frames must not be swallowed or repurposed. Refuse capture overflow rather than searching arbitrary history afterward. The normal source event stream remains complete and unfiltered.

3. **Private mint.** `try_mint_contribution` checks actual SourceEvidence: same Host instance, H5/home, frame/requestRef/ID/pipe, complete write, no write error/in-progress/source limit, one correlated schema-valid result (no error), exact turn. Independently require one admitted item/completed of type agentMessage with explicit phase `final_answer`, exact text, same thread/turn/generation and a successful terminal turn/completed (`status=completed`, no conflicting error/status). Generated 0.160 MessagePhase explicitly permits unknown/null and warns providers vary; unknown is an eligibility refusal, never guessed final. Terminal and item may precede the response, but all must be after the original dispatch cut. Never obtain the item from response.turn.items/history alone. A success response is not a successful model turn.

4. **Proof shape and recheck.** The minted non-Clone/non-Serde capability contains source/capture identity, original role-binding/supply identity, H5/thread/turn/item, request and response/event positions, exact text byte identity and immutable bounded access to selected text. No independent copy of a complete history/journal. `with_current_contribution`/recheck validates live source, original role and unchanged selection/capture under reviewed linearization, then performs only the consuming in-memory freeze decision while guarded; no IO or JSON callback chosen by renderer. A Boolean recheck followed by unlocked use is insufficient. Actual locking between role owner, Host Inner/source gate and CCE working-set revision must be designed and independently reviewed before code—no new reverse lock edge. A consumer-held public DTO cannot rehydrate the capability.

5. **Historical result is separate.** At successful mint retain the exact observed result with its receipt cut and limits. Source closure before mint refuses; a later closed-generation frame cannot complete it. Closure after mint permits only historical recording of that previously minted observation, preserving answer/review standing separately. A new review may bind a historical exact answer only through a newly admitted review request and role custody; it never revives answer authority. Cancellation/replacement closes the capture epoch; late frames cannot resurrect the working set. Cold files never mint a live request, role or emission. R2 persistence is outside this assessment.

## Duplicates, conflicts and capture boundary

CCE needs a tiny source-owned join accumulator fed inside the existing admitted on_line path, not a second transcript. It must inspect response repeats (including those the general journal calls uncorrelated), item completion and terminal conflicts. Exact repeated source facts are idempotent under a named equality method; retain original receipt and at most bounded conflict metadata. Two distinct final item IDs refuse even if their text is equal. Same item/turn identity with different text, phase, tuple or terminal status refuses. A duplicate byte stream receives a new receipt position today; identity/content comparison is needed, not equality of positions. Different-generation counters never order each other.

Mint is an observation at a defined receipt cut, not a promise no later contradictory frame can arrive. A later admitted contradiction invalidates subsequent current recheck and remains a named historical limitation; do not silently replace or erase the earlier minted bytes. Closing source changes currentness without rewriting historical evidence. Defining the exact collision/poison state and final freeze cut is an owning-interface prerequisite.

## Bounds and source serialization

A2/R1 shares one full-payload 1MiB envelope with CAM, with final 64 lifetime identities; do not add a parallel capacity store or reserve account identity at request start. CCE must preflight structured request size and capture budget before dispatch, cap candidate text/IDs/conflict metadata, and count raw decoded UTF-8 plus parsed representation/escaping/reference metadata in final serialization. Use length checks before selected-text allocation and an explicit ownership/transfer plan; cloning SourceRequest/evidence()/observe() wholesale is not a bounded borrowing strategy. Existing read_until/journal vectors are not globally bounded by this proposal; do not claim the entire Host memory footprint is repaired.

Keep message text exactly as decoded UTF-8; no trim or normalization. Parse one complete authored JSON value with duplicate-key rejection and no fences/trailing text, validate C3 references against exact frozen base. Host checks transport/type/phase; C3 validates content and reference semantics. Hash source frames only under a named serde/Host parsed-frame serialization identity, not raw wire identity; exact emitted text is a distinct byte claim. Do not synthesize a positive review disposition absent A2's separately identified schema treatment.
