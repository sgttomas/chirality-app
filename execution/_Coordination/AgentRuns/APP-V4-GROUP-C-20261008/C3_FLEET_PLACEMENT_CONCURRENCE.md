## Fleet compatibility rationale

1. **Future fleet coexistence.** FR-D3 requires project-local records and
   leaves their exact path open. A connector descendant under
   `.chirality/records/` occupies no fleet format or selected fleet directory.
   DEL-06-01 can later select a distinct fleet descendant or another compatible
   project-local location. That later selection remains its own named work;
   sharing a parent directory does not merge formats, writers or custody.
2. **Stable references.** RF-5a identifies the receiving record by its path,
   and carries that record's route account reference (`ra:…`). The placement
   must preserve that logical account identity and provide a stable
   project-relative resolution to immutable account bytes. A filesystem name
   is not a replacement for account identity, source revision or hash. The
   exact safe-key mapping, collision and content-identity rules belong in
   O-D's storage definition; this concurrence does not invent a new fleet
   field, rewrite existing references or automatically adopt format 0.2.
3. **Cold recovery.** A canonical connector directory makes account discovery
   possible from the project alone without a remembered caller-selected
   destination or a live session. O-D must define discovery of supported
   records and visible handling of missing, unreadable or conflicting records.
   Discovery does not authenticate a fact or perform a duty. Existing Group A
   readers are not presumed to find connector accounts.
4. **Independent file access and order.** CFB §6 H-6 reads project graphs,
   decisions and fleet records as ordinary files, not as a topological
   prerequisite. The connector writer/discovery definition needs no common
   reader, service or fleet implementation. There is no new C→D production
   prerequisite and no D-before-C dependency: C's route interface remains
   available to D's later consumers in the accepted A→{B,C}→D→E order.
   Missing fleet files remain source gaps; they do not block independent C
   definition work or create missing fleet production obligations in C.
5. **Meaning is unchanged.** Connector needs remain declared and evaluated
   using standing and the existing per-claim rules, never directory/file
   presence. Missing receiving records remain outstanding; damaged,
   nonconformant or wrong-connector records remain unknown. A satisfied
   connector need can still name a route needed for uncovered parts. A saved
   route account, including an empty-source gap account, does not itself
   satisfy a connector need, make an item ready, complete work or confer
   permission. Human decisions and duty performance keep their actual actors
   and evidence. RF-5b and all historical vendored pins remain unchanged.
