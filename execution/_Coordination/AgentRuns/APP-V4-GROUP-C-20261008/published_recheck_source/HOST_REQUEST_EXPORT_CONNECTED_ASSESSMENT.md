## Exact connected cut

This is an ordinary already-issued request, not a new CCE dispatch. No TASK or manager-role admission is requested. A UI selector may name full H5/RPC/requestRef, but those are lookup selectors only; Host must resolve the original private entry and exact association, never consume caller evidence JSON as proof.

Proposed output: a versioned, closed, source-owned **observation projection**, not a capability. Carry exact original request identity/H5/method and request text with its byte identity; actual attempted/written/in-progress/failed standing; actual send-attempt position if present; correlated response's receipt position and selected bounded response projection if present; original projection/limit flags; and `observed_current_at_capture` versus historical/unavailable. A received position is not required for a written request awaiting response. No final item, terminal-success, role/adoption, answer or review claim follows merely from this export. Unsupported request shape/oversize/missing source yields an explicit diagnostic rather than partial data presented as complete.

Consumer path: C3-owned read-only source/gap inspector, alongside the existing account/answer-only view, receives this projection from the original live Host lookup and shows request/write/response status separately from the selected cold account's recorded claims. It must not insert the projection into account0.5, upgrade recorded-source authenticity, or use byte equality to join it automatically to a cold answer. The ordinary Host request list supplies selection; C3 can display any missing original association as unavailable. Original project association must be supplied from its actual owner if present; do not assign the currently opened project to a request by convenience. A caller-provided request reference with no retained matching Host source remains unavailable.

This is a useful production reading of actual existing request evidence and its gaps. It is not yet implemented, and the current C3 reader has no such live-input path. They are a source basis, not a bounded immutable export contract.

Do not wrap `check_source` followed later by `evidence()` as an atomic capture: they acquire Inner separately. The new owning capture must verify original Host/entry/frame/ref/generation and read all selected fields from that same entry under one Inner guard. Account/auth methods stay outside this first cut; preserve all existing sensitive projection/redaction limitations. Do not clone the full journal, NativeHistory page or all request records. RoleBinding remains separate and is not needed to truthfully inspect a request; no generic bind, agentRole or dormant call-custody handoff is promoted into answer attribution.

Missing method contract: exact projection format/version, selected fields and omitted-field semantics, exact UTF8/text and JSON byte method, currentness-at-capture cut, size/depth/allocation/error handling, and how C3 consumes unsupported/missing sources. G0's proposed method names are not already adopted serializers. Do not alias AA-CAP-PF1 to raw artifact SHA or wire bytes. ## Locks, closure and retention

Resolve home/request selectors through actual owner routing, release that routing lock, then take Host Inner once for source validation/capture. No C3/role callback, filesystem resolution or storage write under Inner. Bound source sizes before cloning selected text/response. Capture is a point-in-time observation, not a persistent currentness promise; closure immediately afterward does not make the copied observation a live lease. Source missing/replaced before capture refuses. Same-process historical reading is possible only while exact original entries still exist; process loss/cold files cannot recreate them. A later read recomputes availability without silently finding a newer request.

No new R2 N/S/D/T/Q or immutable store is needed for this transient cut. A specific exporter/readout budget is still required before code; existing one-MiB reader limits do not bound Host.evidence's current clones. Do not claim durable recovery or complete critical closure from a transient response. Current Host/REC meaning need not change; the new projection method and consumer still require named owning technical adoption.
