## 1. Actual availability and joined cut

include generation/requestIdentity/method but do not generally expose the private
SourceRequest.request_ref. They are not complete observation selectors and must
not be augmented by guessed requestRef text or public evidence JSON. The Host

and an exact single-request read; neither exists as this production API yet.

Do NOT place this unassociated inspector beside project C3 panels by default.
Implementation is DEFERRED pending an actual initiation-bound project/question
association producer for the preferred C3 use, or separate selection of the global
diagnostics alternative in §7. The retained technical method reads already-issued
original single-text turn/start requests; it does not start a request or upgrade
a cold account. No standalone exporter code release follows from its feasibility.

## 3. Precise presentation and independent state domains

Render a source-owned observation as five separate groups:

1. Selected inspection context: actual active home and App project display,
   clearly labelled CURRENT SELECTED CONTEXT, not original request ownership.
2. Original request: exact H5/RPC/requestRef, turn/start and thread identity only
   when the original source supplies it; exact decoded UTF-8 single text with
   raw-text byte length/digest. Render as escaped plain text, never Markdown/HTML.
3. Local request write: original registered/attempted/in-progress/complete/failed/
   unknown state and actual attempt position if supplied. Complete local write
   is not response, terminal success, adoption or delivery to a model.
4. Correlated response: independently absent/present result/present error or
   unavailable as projected; response position/digest if supplied, no full payload.
   An observed response does not erase a concurrent/failed/in-progress write.
5. Capture standing and limits: current_at_capture versus historical retained or
   unavailable, original projection/redaction/shape limits, and “Original request
   project association: unknown — not supplied by this source”.

Exact source state names come from Host's frozen projection, not these descriptive
labels as an invented wire enum. SourceEvidence presently lacks request-bound
project association; do not backfill from later REC conversation metadata or
current App workspace. Unknown is useful information, not permission to guess.
H5 currentness is a point-in-time capture fact only, not a durable lease. If the
observed active generation later closes/changes, keep any displayed result only
as explicitly historical capture (or clear it), never continue a live claim.
A new click rereads; no automatic polling/retry/supplier activity.

The inspector holds at most one selected observation and one bounded selector
page in component state. A new selection clears the prior observation before
starting the read. Selection/request counter and active-home/project context cut
must match before installing a response; compare echoed exact selector too.
A slow response after home switch, page selection change, unmount or superseding
read is discarded. Do not persist exported text in localStorage, logs, account,
journal or RS, and do not cache one full observation for every listed source.
UI pending flag is not a Host concurrency or allocation guarantee; owning budgets
and command concurrency must be enforced independently as the joint source defines.

## 4. Failures, privacy and non-promotion

Command stale/busy/routing error and source typed unavailable remain distinct;
show a safe reason and no fabricated request text. An unavailable new read cannot
leave the previous request looking like the current selection. Oversized or
unsupported source shape reports unavailable, never silently truncates selected
text while presenting it as exact. No source means no digest/receipt invented.

Only the explicitly selected original single-text turn/start is eligible. Auth
methods, credentials, supplier configuration, attachments/multipart fields and
unrelated response details must not leak through the projection. Method filtering
belongs to Host, not merely hidden UI options. Output includes only bounded selected
fields; do not stringify the entire raw Host snapshot or response into this panel.
The existing generic lifecycle display remains its own surface, not this budget.

Decoded text identity, pinned parsed-Value digest and original wire bytes are
different; never label a parsed projection as wire evidence. Preserve actual
redaction/absence flags. A displayed exporter/recorder context is distinct from
request initiator. This external observation is not an RS record or critical-set
carrier; request/write/response states are not RS resolutionAtWrite. Preserve an
RS literal only if a real source RS ref exists, which this slice does not invent.
No diagnostic→RS projection, role/adoption/answer/review/terminal/human-act claim.

A cold account with matching text/hash or copied selector JSON cannot become a
live source association, original acknowledgement or authored contribution. The
cold panel stays independent, with its own recorded-source limits. No automatic
selection based on account hashes, claimed actor or request text. Process loss
loses original runtime availability; the UI cannot hydrate it from stored bytes.

## 7. C3-REQUEST-PLACEMENT-01 — product value and deferred implementation

Product-fit finding against consumer0f76d441: a same-home unassociated request
may expose another project's original text, while its write/response state says
nothing about the selected C3 question. Placing it beside project C3 panels could
imply relevance not established by any source. Technical source correctness and
bounded export do not by themselves justify that placement or implementation.

Preferred C3 dependency: actual App-owned original project AND question association
bound at initiation/dispatch by its owning source cut. Such a producer must retain
the real association and its limits; it is not a new caller field, a role claim,
current context, later REC index or cwd inference. No association producer is
implemented or selected here. Its source/authority/lock/retention and consumer
meaning require separate owning design. Until available and selected, this export
does not advance full C3 reconstruction or establish any question/account linkage.
No new producer is invented merely to remove the hold.

Alternative ONLY if separately selected for diagnostics: a collapsed GLOBAL Host
diagnostics surface, not default placement beside project C3 panels. Its default
is metadata-only: no auto-selected request, no automatic observation read, no
request text fetch/display on mount, refresh, page arrival, navigation or selection.
The user explicitly selects a request AND invokes Read observation after a clear
UNASSOCIATED — MAY INCLUDE OTHER PROJECTS disclosure. Metadata page contains only
Host selectors/skipped counts; request text requires that separate action. Selection
alone never reads text. Close/hide clears transient selected text; no automatic
refresh, persistence or remembered text. In-app global diagnostics still needs
reviewed visibility and privacy behavior; the heading is not permission by itself.

The alternative's useful result is narrowly original-RPC registration/local-write/
correlated-response diagnosis. It proves no terminal completion, delivery
acknowledgement, project ownership, selected-question answer, role adoption or
human act. It never attaches to a cold account, auto-associates by matching text,
or lends evidence standing to the current project. Existing broader Host debug
surfaces do not justify adding another implicit cross-project text exposure.

Decision standing: recommend DEFER this implementation for the preferred C3 use
pending genuine original association; retain the deferred Host87034 method as a technical
option only. Global diagnostics remains an unselected alternative. No standalone
exporter, new UI placement or code is released. Host/RS/independent review should
assess this exact value/placement boundary separately from method correctness.
