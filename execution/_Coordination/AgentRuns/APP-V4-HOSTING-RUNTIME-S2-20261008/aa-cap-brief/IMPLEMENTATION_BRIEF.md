## Frozen parsed-frame identity method AA-CAP-PF1

Input is the already parsed, admitted serde_json::Value, not raw wire bytes. Domain-separated SHA-256 stream: ASCII `chirality-aa-cap-pf1` then one zero byte then deterministic compact JSON bytes. Object keys are sorted lexicographically by their UTF-8 bytes; arrays retain order; no Unicode normalization, trimming or omitted fields. Null/boolean/integer/finite-number/string encoding uses the exact locked serde_json serialization rules. Record Cargo.lock and method version; a dependency behavior change needs vectors/review, not an implicit same-method identity. Signed/unsigned/float lexical distinctions already lost by parsing are not claimed preserved. Existing Host parse behavior, including duplicate wire keys, is not repaired or called raw-wire identity.

Preflight borrowed Value with a bounded visitor before serialization: depth≤16 containers; total nodes≤4096 (count every value plus every object key); members/elements per container≤128; any JSON string value≤65536 UTF-8 bytes; key≤256 bytes. Then serialize once through a counting hash sink, stopping before accepting byte262145. No to_vec/string of the whole frame and no cloned Value. Sorted-key scratch uses bounded borrowed references, released per container; recursion depth enforced before descent. A limit failure produces CaptureLimit and stops core processing, while ordinary Host delivery/retention continues unchanged. Method never hashes a truncated prefix as a successful identity.

Exact repeat means same generation, identity tuple and PF1 digest. A second receipt of equal parsed content is idempotent; changed timestamp/extra field is conservatively a conflict, not silently excluded. Distinct final item IDs conflict even with equal text. Cryptographic collision resistance is the named identity assumption, not a byte-equality theorem. Authored text identity, if useful internally, is SHA-256 of exact decoded UTF-8 plus byte length; it is never a minted authored artifact.

## Frozen core shape checks — no full native-schema claim

Do NOT call validate_native_result/jsonschema from AA-CAP hooks. Existing helper reparses the863788-byte supplier schema and constructs/formats validator output per call; those new allocations cannot fit this core budget. Do not hide them as existing cost or add a new global validator cache in this slice. This core checks only the finite fields needed for its provisional tuple, using borrowed Value accessors after PF1 preflight. It emits an explicit `nativeSchemaValidation=not-performed-by-core` limit; no status name/report may claim full native schema validity. Existing ordinary Host validation stays unchanged. A later attributable issuer must perform full owning validation outside Inner under its own reviewed allocation/recheck design.

Exact predicates: selected original request has method turn/start, nonempty threadId, one input element of type text with string text and empty text_elements; no extra request parameters admitted to capture. Response has original scalar id, no method or error, object result with turn object, nonempty id, array items, and status inProgress/completed/interrupted/failed. Only successful completed terminal can qualify. item/completed has object params, nonempty threadId/turnId, integer completedAtMs, item object with nonempty id, type agentMessage, string text and explicit final_answer phase. turn/completed has object params/nonempty threadId, turn object/nonempty id, array items, status completed, and absent/null error. Missing/type-mismatched fields refuse capture; optional/extra fields are included in PF1 but not validated against the entire supplier schema. Unsupported values in the selected fields never become success. This is an exact subset for internal evidence consistency, not a substitute supplier schema.

Checks use no deserialization into cloned trees, formatting of schema errors, or allocation based on untrusted lengths. Store fixed reason enums; any presentation of reasons is test-only outside Inner. Negative vectors must prove a frame can meet these selected predicates yet is not certified native-schema-valid; readout preserves that limitation.

## Candidate development limits

- One capture slot per Host, one selected request, one early candidate turn, one response fact, one final item, one terminal fact and one first conflict reason; no accumulated duplicate/conflict list.
- Each H5 string, thread/turn/item/requestRef and similar retained identity≤256 UTF-8 bytes; request ID remains original scalar with its bounded representation. No truncation.
- Request text and selected message text≤65536 UTF-8 bytes. Relevant parsed-frame serialization≤262144 bytes by PF1; text is borrowed/hashed and not copied into the core.
- Retained core owned data≤8192 bytes, visitor/sort scratch≤65536 bytes, streaming hash sink fixed workspace; total incremental core-owned heap+scratch≤131072 bytes. Implementation must measure/account capacity, not just string length; use fixed-cardinality structs, bounded strings/borrowed references and checked arithmetic. No hidden vectors sized from incoming lengths. This is below the existing1MiB development envelope, not a bound on pre-existing Host journal/parser/SourceRequest allocations.
- Capture revision/epoch counters are checked u64; exhaustion retires/unavailable, never wraps. No capture-level memory reclamation policy changes existing Host source history.

Boundary and one-over vectors are required for every numeric limit. These are synthetic development ceilings, not final provider message suitability. If implementation cannot demonstrate them without extra payload copies or protocol changes, return the exact failure before widening scope.

## In-process transport adapter (selected for tests)

Use an anonymous OS pipe, not /bin/cat, Host.start or a fake supplier process. Create pipe descriptors, set FD_CLOEXEC on both, wrap write end as OwnedFd→ChildStdin and read end as owned File; bind it to a synthetic ready Host with no Child. Rust documents From<OwnedFd> for ChildStdin (stable1.74) requires a CLOEXEC pipe: https://doc.rust-lang.org/std/process/struct.ChildStdin.html . Retrieved docs1.99 are API guidance, not proof of the eventual compiled toolchain; verify compile support after release.

Actual-pipe positive requests are deliberately small (≤1024 serialized bytes), read end retained throughout; drain exact newline frame with a1000ms total poll/read deadline and a2048-byte acquisition ceiling, then byte comparison. Timeout fails the fixture; no retry loop beyond that deadline. Use nonblocking writer mode for tests so a full pipe returns error rather than deadlocking; actual successful small writes still pass existing write_complete/write_all/flush. No socket substituted for a pipe, no process, signal, launch, wait/reap, group action or native App. Descriptor RAII closes only these in-process test resources. Avoid a real broken-pipe SIGPIPE case: write-failure/partial-write outcomes are explicitly simulated below, not produced by closing the reader.

Add narrowly cfg(test) transport scheduling hooks only at after-admitted-prewrite/before-write and after-actual-write/before-settlement, outside Inner/source gate (frame_write may remain held). Inject only synthetic response/notification frames here; no automatic-reply request in a reentrant write hook. This forces early event/response ordering without a worker thread. Synthetic frames are not supplier observations. Successful-pipe tests MUST read the actual original outgoing frame and show the real write_complete branch set written.

For partial/failure control, cfg(test)-only write adapter supplies an explicit Err before real write or after a controlled reported partial attempt; label these `simulated write settlement`, never actual kernel partial-write evidence. Do not claim they qualify the transport. Pure core vector tests likewise explicitly feed simulated facts. Production write_complete is unchanged. Actual no-attempt refusal (closed/replaced pipe/generation before prewrite) can be checked without writing. All descriptors are held safely; no test helper spawns child processes.
