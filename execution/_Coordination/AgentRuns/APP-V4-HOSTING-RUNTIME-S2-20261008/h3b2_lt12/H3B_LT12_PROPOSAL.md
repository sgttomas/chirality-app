Read-only basis: current main `3d73db745edd3378e0bb254a1b263215ef0861e9` after PR #1153. First LT-23 implementation was merged in #1152. No code, checkout change, build, process execution or export performed for this proposal. Parent technical release follows Host/RS/REC concurrence and independent review; this document does not release code.

## Actual contribution and unchanged meaning

Add only actual same-H5 **LT-12** (`ready / child-ended-without-stop-record / exited-unexpectedly`) after a successfully installed same-source LT-09. Preserve the whole actual event, including at/sequence, exitFacts and closedGeneration. A zero exit code still belongs to LT-12 when no App Stop owns the ending. No descendant census, zero-survivor claim, new integrity probe, renewed custody or observation-phase change follows. Publish a fresh single-event S1 closure associated with the original immutable pre-spawn observation. Existing full S1 reader accepts this row; add only explicit producer support, without schema/semantic weakening.

Current on_eof first captures the owning PID, calls wait only on that captured child, then takes attachment_gate and Inner and checks full generation again. Preserve that existing wait behavior and source scope. Preserve close_generation and its primary execution-loss/request-register closure/persisted summary facts and returned unknownNoResponse/endedUnanswered counts in their current order; the artifact worker copies the already captured counts, never recomputes them. If state is stopping, on_eof appends the actual exit journal fact and notifies Stop; only Stop emits LT-23. A superseded EOF cannot emit a current LT-12 or close another source. Do not move child wait, add descendant handling, or change REC flush ownership.

## Capability and event sequencing

Retain one additional private **original installed LT-09 reference** per current Host generation, separate from successor_reference (the selected latest receipt). Set it atomically with successful LT-09 installation under the existing controller→Inner guard. Retain existing installed flag for compatibility with test-only exporters; eligibility requires the genuine retained reference as well. Clear both original and latest references on the next accepted start attempt and Host drop. This is one retained predecessor, not a historical index, serialized capability, per-event list or indefinite retained Host. Store LT-12 and LT-23 publications both read this original predecessor, even after current receipt becomes LT-12. Original LT-09 artifacts remain immutable/readable through genuine existing holders.

At actual LT-12 emission under Inner/source gate, reserve its exact sequence for **every successor LT-12**, even if its LT-09 publication is still pending or unavailable. Capture event, start_attempt, full H5, closed target kind and original predecessor together. A later LT-09 success/error cannot override this reservation; ineligible LT-12 remains unavailable. Generalize the private terminal token to a closed row/state pair: LT-12 requires exited-unexpectedly; LT-23 requires stopped. Never accept any arbitrary closed state or infer row from a caller boolean. Pending/reason projection must identify the actual target row rather than calling all jobs LT-23.

After releasing Inner **and attachment_gate**, make the same nonblocking scheduler admission used by LT-23, then run the existing recovery flush in its original post-lock position. No Store reads/hashing/copy/sync, namespace lease acquisition, controller wait on a worker or REC writer acquisition is added inside EOF/source locks. Reuse exactly the one AppRuntimeCustody controller/active permit across LT-12 and LT-23, all homes and reopened Hosts. No second worker allowance, queue, join, automatic retry, cancellation promise or production timeout. Pending is set before spawn; busy, missing predecessor/custody, spawn failure, ordinary error and caught panic remain truthful unavailable. All Store/namespace guards unwind before controller→Inner completion. Completion requires matching attempt/H5/actual sequence/target state and non-closing controller. Weak Inner ownership, fail-closed poisoned-controller behavior and closing-before-Exit/REC hooks remain unchanged.

## LT-12 → Stop or restart

When Stop begins from exited-unexpectedly after an LT-12 reservation, invalidate that LT-12 job **at actual stop-request event emission** under Inner: advance the publication ordering reservation to that actual event sequence, clear its pending display, and show evidence unavailable for the in-progress later transition. This is only an ordering/availability fence; do not publish an envelope for the intermediate Stop row or alter its legacy bytes. Limit this extra invalidation to the newly supported LT-12 source case, preserving existing ready/handshaking Stop eligibility semantics. Later LT-23 emission reserves its own exact sequence and uses retained original LT-09, never the current LT-12 reference.

If the LT-12 worker still holds the App permit, LT-23 admission is busy/unavailable and is not retried when LT-12 finishes. That stale LT-12 completion cannot overwrite the later reservation. If LT-12 already completed and released the permit, LT-23 can publish a separate same-H5 closure from the same original LT-09. If Stop wins the original EOF gate first, preserve the existing stopping→exit-journal branch and produce no LT-12 job at all. This makes the two actual orderings explicit without inventing global event chronology.

Current start accepts absent/stopped/refused, **not exited-unexpectedly**. Keep that behavior: direct start after LT-12 remains refused, no LT-13–16 or automatic restart is added. Test source replacement through the existing Stop-then-start route; old LT-12 success/error/panic cannot mutate the new attempt/H5. Existing Stop-from-exited-unexpectedly chooses LT-19 through its fallback, and the ready EOF branch does not append the stopping-branch exit journal entry. Consequently its intermediate legacy row and later Stop fallback exit facts are existing source limitations; this slice neither rewrites that row nor synthesizes missing exit facts. RS/Host review should retain these limitations explicitly rather than presenting the whole legacy trace as newly validated. No automatic Stop is triggered by artifact publication.

Existing reference/reader identities and source guards remain exact; changed hosting/Store bytes require Group B fresh committed-source receipts and named receiving/pin adoption. The LT-09 v1 and LT-23 terminal export formats stay unchanged and must continue rejecting LT-12 as unsupported. A future LT-12 consumer exchange is separately scoped; no new exporter format is smuggled into this slice.

No production lib/setup/REC schema or implementation changes anticipated; any need to change REC closure meaning/order, descendant policy or other lifecycle rules returns to parent. Do not edit canonical schemas/Design/pins, Group B, exporters' contracts, UI, roles/workflows, S3/SEAL-2 or MEMORY.

Deterministic offline controls in both feature states: invented child reaches installed LT09, then exits without Stop (zero and nonzero exit); exact actual LT12 event/closure counts and H5, unchanged observation/predecessor, established closed-view native read; fresh receiver remains unavailable. Block artifact work and prove EOF accounting/closure and Stop remain independent; one shared permit across LT12/LT23/another home; busy/failure/panic/immediate completion settle truthfully. Exercise Stop winning EOF gate, LT12 captured before Stop with late completion, successful LT12 then successful LT23 from original LT09, Stop/restart while LT12 worker blocked, late LT09 success/error after ineligible LT12, closing before/during completion, stale EOF source, repeated EOF, foreign tuple/row/sequence/predecessor, selected closure/source tamper, namespace busy/rebind and original replaced-root no-write control.
