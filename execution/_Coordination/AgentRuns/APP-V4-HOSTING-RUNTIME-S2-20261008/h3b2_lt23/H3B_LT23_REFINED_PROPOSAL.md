## Chosen ownership and behavior

Add one private terminal-publication controller to existing AppRuntimeCustody, shared by every home and reopened Host in that App session. No global singleton, new Runtime layer, per-Host worker allowance, queue, automatic retry, or numerical latency promise. The controller owns at most one active job permit. A busy controller, absent App custody, ineligible predecessor, or thread-spawn failure yields terminal evidence unavailable; Stop still reports its operational result. After obtaining the permit, establish pending under controller→Inner with the exact reserved attempt/H5/event token before spawning the worker; release both locks before spawn. Never assign pending after spawn returns. A successfully spawned job leaves that pending state until actual completion; spawn failure settles only that same still-current token as unavailable and releases the permit. It does not claim durable publication or successful cleanup beyond the unchanged legacy facts.

At actual LT-23 emission, under Inner, reserve the latest publication event sequence for **every** successor Stop, including ineligible ones. Capture exact event, attempt, full H5 and the already successfully installed same-source LT-09 reference together. Release Inner before scheduler access. Eligibility requires that prior LT-09 installation; Stop racing an unfinished LT-09 stays unsupported. Both LT-09 success/error installation and terminal installation must respect the reserved event sequence, so late LT-09 cannot regress or poison terminal status. Keep original observation bytes/phase and immutable LT-09 publication. No collection/index or public history API is added.

After process input closure, grace/kill handling, EOF accounting and LT-23 emission, attempt nonblocking job admission. Do no Store/namespace/filesystem work on this Stop path. Capture a private job containing Store Arc, native-held prior reference, exact event/source token and Weak<Inner>; never retain Host or AppRuntimeCustody strongly. The detached worker owns only the shared controller Arc and these bounded inputs. Run publication/readback inside a caught-unwind boundary. After normal return, error, or caught panic has unwound all Store/namespace guards, use the common controller→Inner completion path: settle matching pending to success or unavailable (panic is unavailable), subject to identical attempt/H5/event and closing checks, then release the permit with an unwind-safe guard. Do not install from a destructor while Store guards are held. A stale or closing completion cannot mutate source state. Process abort has no live completion guarantee. Spawn failure uses the same token-scoped unavailable settlement and releases its permit immediately. Do not retry failed or busy jobs automatically. Stuck I/O retains this single permit and its one bounded closure across dropped/reopened Hosts, rather than accumulating threads/jobs.

The worker runs existing full Store publication/readback under existing namespace/selected-anchor/descriptor guards. After work, it upgrades Weak<Inner> only for a short installation check; upgrade failure discards installation. Compare attempt, full H5, exact reserved LT-23 sequence and terminal eligibility before installing success or unavailable. A completed stale artifact may remain immutable on disk; no new-source mutation or implicit index follows. Do not hold Inner during Store work. Preserve prior reference internally on failure, but native display reports terminal unavailable rather than presenting LT-09 as terminal success.

## Closing and lock order

Use a small controller state lock solely for open/closing, active permit and installation serialization. Scheduler uses try_lock and fails unavailable on contention. Installation holds controller state then briefly Inner; all emission/capture paths release Inner before scheduler access. No path may acquire controller while holding Inner, REC writer, source/attachment gate or namespace lease. Worker releases all Store/namespace leases before controller/Inner installation. Neither controller lock nor Inner may cover filesystem I/O or thread joins.

Add an explicit App-closing hook on AppRuntimeCustody, invoked at the beginning of lib's existing RunEvent::Exit branch **before** iterating home Stops; invoke it defensively before record_app_session_end's existing REC writer acquisition too. Closing is serialized against the short installation section: installations linearized before closing remain; after closing, new jobs and installations are disabled. Closing never joins, polls or waits for worker completion. A short in-memory controller critical-section acquisition is distinct from waiting for the job; it must never contain I/O. Shutdown Stop consequently reports terminal unavailable/closing and does not start a job. Restart does not close the App controller and never waits for its active job; a restarted source simply invalidates installation tokens.

Blocked filesystem calls are not cancellable by this design and no timeout is invented. A detached worker may finish or remain blocked until process termination. If it holds a namespace operation lease, new namespace admission may remain retryably busy; this cannot stall Stop/restart/shutdown on the job. Existing unrelated REC/session-end behavior is preserved, not newly claimed to be nonblocking. Pending display while alive is truthful; on closing display must report disabled/unavailable rather than promise a future install.
