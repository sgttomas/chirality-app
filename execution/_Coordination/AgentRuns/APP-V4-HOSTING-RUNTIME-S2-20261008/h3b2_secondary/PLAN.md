## Proposed smallest coherent sequence

1. Extract a no-write Store geometry preflight: proposed complete namespaces must exclude actual app-data/distribution, vendor and selected source physically, using existing nofollow/physical rules. It must validate current Store root identity and selection association when a Store exists. Preflight account plus prospective key Store before bootstrap.prepare_key, alongside existing REC and attachment preflight. Production None or required Store configuration failure refuses before home materialization.
2. After prepare_key, rebuild actual complete namespaces and repeat all relevant geometry checks. Home materialization may remain on failure as existing behavior; explicitly distinguish that from authority/binding admission. Existing bindings, held references and evidence remain unchanged on any failed admission.
3. Preserve Store object/root/selection and native-held reference identities. Use a shared replaceable namespace binding cell owned by the Store, not a freshly cloned old Store. Every Store operation holds a read lease for its entire reliance; retained old Arc handles use the same cell. Rebind takes a nonblocking exclusive lease: if an existing read/write is active, refuse admission before REC mutation, rather than blocking a global writer behind full inventory/hash/probe work. Refactor nested guard calls to use the operation's lease without recursive RwLock acquisition.
4. Add a narrow coordinated commit interface: prepare/revalidate Store candidates outside REC writer, acquire Store exclusive lease first without waiting, then REC writer with established lock ordering (must audit against existing attachment/source paths). Under guards perform final bounded geometry/current-binding checks, all fallible REC validation, then REC assignment plus infallible Store cell replacement before releasing either guard. Do not run selected closure hashing/probes under REC writer. A prepared proposal must bind old namespace revision and exact Store root/selection identity; changed proposal refuses. Do not implement rollback by blindly restoring an old Arc after other operations may have observed new authority.
5. Install the admitted namespace projection/attachment capabilities through the existing Root sequence and configure the new key Host with the same admitted Store capability before starting it. Avoid fallible Store creation after REC commit: prepare the capability ahead of commit. New key Host has no prior reference; account retains its references. Any Host/router construction failure after namespace commit must be explicitly a post-admission setup failure, not reported as failed namespace admission with unchanged bindings. Prefer preparing fallible new-home/session objects before commit if their registration effects can be shown harmless; exact source audit required.

## Atomicity constraints requiring review

A Store-only binding lease suffices to prevent old Store guard bypass, but does not itself atomically replace AppState and attachment capabilities. Existing attachment operations retain old immutable bindings too. Do not claim a system-wide transaction. Either prove the narrowly scoped extension preserves existing admission behavior while Store/REC share the commit boundary, or expand only the needed Root admission coordination with source-owner concurrence. No broad namespace redesign is presumed. All disk observations remain bounded, not filesystem snapshots. Source mutation between final check and action retains existing limits.
