## Chosen minimal design

Introduce one App-lifetime native namespace authority with an epoch and current immutable NativeNamespaceBindings behind a read/write lease. This is an internal protective capability, never serialized or reconstructed from JSON. Its source is Root's existing received/planned home declarations; it cannot invent homes, H5, supplier standing or write domains.

Store retains the same object, physical root ID, vendor/selection and native-held references. It obtains the current authority read lease for each entire read/publication reliance. Previously cloned Store Arcs therefore observe current namespaces; an operation begun under the old epoch completes before admission or causes admission to refuse as busy. Do not cache a safety boolean.

Each AttachmentCustody capability carries the authority plus its admitted epoch. Every attachment operation obtains a read lease and checks epoch equality before any metadata read/write or send reliance. A retained old capability after a successful epoch change returns an explicit stale-capability refusal; it never silently adopts new authority and never writes under the old subset. Root installs freshly prepared attachment capabilities for the new epoch. Prepared dispatch retains its original capability: if admission occurred before dispatch lease acquisition, it refuses before send. Existing durable metadata and actual request history are not rewritten. A late outcome persistence through a stale capability reports unavailable, preserving its actual response/history rather than fabricating a durable result. Outcome-only automatic rebinding is excluded from this slice; the attachment owner concurs with explicit stale refusal and retained visible live facts.

Use operation read leases, not only an epoch check at the end: after-the-fact rejection cannot undo a stale write. Attachment dispatch holds one read lease from its first custody validation through final source validation and actual pipe write; explicitly drop the dispatch lease after the actual write and hot in-memory write-result update, before the existing inline call to persist_attachment_observation at hosting.rs1705. That call must acquire its own independent operation lease through the retained AttachmentLink capability; no recursive acquisition. Also release before response waiting. Admission may win between these phases, in which case persistence reports stale/unavailable without altering actual write history. Publication/check/replace/cold-read operations each hold their own lease. Internal guard methods accept that lease, avoiding nested lock acquisition. Provide lease-taking internal variants for publish_prepared, check_prepared, replace_observation, resolve_cold, path guards and Store nested publication/read helpers. lock_sources returns an ownership wrapper whose lifetime is tied to the borrowed namespace lease, preventing a file-lock capability escaping its protective lease; dispatch passes the same lease into every nested call. This lease does not serialize normal readers. Admission uses try_write and refuses promptly when any operation is active; it never waits behind hashing, picker revalidation or pipe IO while holding REC writer.

## Lock order and boundaries

Proposed acquisition: namespace operation read lease → existing attachment frame_write → custody ownership lock → Host attachment_gate → Inner, respecting current dispatch order. Release source locks before independent outcome persistence. No operation should acquire namespace lease while holding those lower locks; helper calls reuse the passed lease. Store read/publication lease ends before later Host Inner/final spawn checks.

Admission: key_setup → namespace try_write → REC writer.try_lock → existing REC preflight source/ledger locks. No Host attachment_gate or frame_write is acquired by admission. Root slot replacement occurs without invoking Host IO or fallible callbacks. Audit homes/attachment-slot lock acquisition against command entry paths; commands must release slot/home lookup locks before acquiring operation lease. Current submit_attachments clones the capability then releases the slot, which fits this order.

Current examined Store call sites have no REC→Store path. REC append paths should continue using their writer-stabilized immutable binding rather than acquiring a namespace read lease beneath REC writer: otherwise writer→authority would oppose admission authority→writer. Joint commit alone keeps that ledger binding synchronized. This is not a blanket claim that all App operations become transactional; only REC protective binding and Store/attachment namespace reliance participate. Source-owner review must verify every custody entrypoint and callback, including lock_sources and nested publish_prepared/check_prepared, before implementation.

Long IO may hold a shared operation lease, causing admission to return busy, but no global REC writer or exclusive admission lease waits on that IO. Never stop a turn, drop evidence, or force admission to obtain the lease. External filesystem mutation remains bounded-observation risk; no atomic filesystem snapshot claim.

## Reviewed refinement: stale read/hot-join compatibility

Source evidence: hosting.rs1708–1715 persists through AttachmentLink.a.custody, not the current HomeSession slot. hosting.rs1721 resolve_attachment_submission first calls custody.resolve_cold and then requires Arc::ptr_eq(custody,&a.custody) plus generation/association/record equality before any hot source augmentation. Replacing the HomeSession attachment slot cannot restore the old request's hot join.

Under the proposed stale-epoch design, an old capability's cold read is explicitly stale/unavailable; it cannot produce a current read standing. A fresh capability may read old immutable records only under current full namespace checks, but its pointer mismatch must retain cold/historical-only standing: no nativeTurnRef, resumed/hot status, automatic retry or claim that historical prepared-not-sent proves no current send. Existing hot request/reply facts remain in their genuine Host source; they are not rebound through JSON or a substituted Arc. Do not change Arc::ptr_eq to structural equality or replace AttachmentLink.custody merely to recover display continuity. Add an explicit compatibility limitation for the namespace-admission boundary where needed, rather than silently implying the fresh cold read is the old live source.
