## Required refinements

1. **Settle REC-unavailable admission, currently unresolved in step 4.** Current AppRuntimeCustody::bind_native_namespaces first validates geometry, then returns successful unavailable observation when ledger is None, with bindingCommitted=false and no new ledger. Recommend preserving that behavior: admit the protective authority and Root capabilities after all checks, record protective admission separately from REC binding, retain initial_limit and queued actual facts, never open/replace a ledger. Missing configured REC leaf or failed geometry still refuses before admission. If a different branch is selected, name its exact compatibility consequence before code. Include both unavailable-valid-geometry and unavailable-invalid-geometry controls. Do not claim synchronized durable REC binding when none exists.

2. **Specify lease endpoints at the actual dispatch call graph.** dispatch_attachment_turn calls check_prepared, later lock_sources/check_prepared, writes the captured pipe, then calls persist_attachment_observation inside its closure. One outer namespace read lease must precede first custody check and survive the actual write; explicitly drop it before that persistence call, not merely at function return. Otherwise persistence taking its own lease can recursively read-lock the authority. publish_prepared currently calls lock_sources, supplies_path, client_path and check_prepared; replace_observation and resolve_cold similarly nest guards. Supply lease-taking internal variants for all these paths and prevent lock_sources returning ownership detached from its namespace lease. Apply the same discipline to Store nested guard/read/publish calls. Test active dispatch contention, post-write admission before outcome persistence, and nested helper completion with barriers. No later source callback may acquire authority beneath frame_write, ownership, attachment_gate, Inner or REC writer.

3. **Make the old hot-link limitation explicit.** AttachmentLink retains the original custody Arc, and resolve_attachment_submission requires Arc::ptr_eq with that Arc after a successful cold read. A new Root slot cannot restore the old hot join. Under the proposed epoch refusal, old prepared dispatch and late outcome persistence refuse; raw SourceRequest response/history remains, but old durable/hot reference projection can be unavailable. This is faithful only if the owning attachment contract concurs with that precise loss of availability. Do not say old attachment references remain normally readable merely because account Store references do. No automatic retry/rebind, replacement record or inferred native turn is permitted. Add a response arriving across admission test verifying actual response retention, explicit custodyLimit, no resend and no false current durable/nativeTurnRef claim.

4. **Close preparation and exposure boundaries concretely.** Host::new_with_app_custody has registration effects; a preconstructed Host is not necessarily inert. Specify whether it is prepared without shared registration, or registered precommit with truthful cleanup/retention on refusal. Final fallible REC checks must precede either binding assignment; existing RecoveryLedger::bind_namespaces itself is fallible, so the prepared/commit split must be concrete and private. Compute checked next epoch before mutation. Root projection and slots must be installed before exposure, using no callbacks that reacquire authority. If later HomeSession/router preparation can fail, report post-admission failure explicitly and retain committed protection. Do not reuse current lib refusal wording 'original bindings retained' for a post-commit failure. Tests must inject each final-check and post-admission failure independently.

## Lock order and acceptance fence

The proposed namespace → frame_write → custody ownership → attachment_gate → Inner order fits the inspected dispatch path if nested helpers use the existing lease. Admission namespace → REC writer → source/ledger locks fits existing REC preflight, provided REC never reaches back into namespace/Store guards. Audit all slot/home lock callers before holding exclusive authority while replacing slots. Current submit_attachments releases both lookup and slot locks before runtime submission, which is compatible.

Prefer nonblocking REC writer acquisition after successful namespace try_write; otherwise explicitly account for exclusive authority waiting behind REC activity and bound its liveness consequence. This is a required implementation choice/lock test, not a demonstrated existing deadlock. The proposal must not claim prompt admission refusal for writer contention unless implemented. Do not stop active work to obtain either guard.

Retain required negative controls from the proposal: old Arc and old PreparedDispatch after expansion; active lease busy without state change; failed final check without mixed binding; expanded-domain drift; same Store root/selection/reference preservation; new key membership without cross-home H5; no exposure before all capabilities; no issuer or JSON rehydration. Explicitly exercise existing unavailable Store/error cases rather than silently treating them as safe. Geometry/ID final checks are bounded observations; they do not supply an atomic filesystem snapshot or replace selected closure checks.

No canonical meaning change is established by this review. Resolve the four refinements with attachment/REC/setup owners and record the chosen behavior, then independently review exact implementation and synthetic schedules. Code hold remains appropriate until that fence is complete.
