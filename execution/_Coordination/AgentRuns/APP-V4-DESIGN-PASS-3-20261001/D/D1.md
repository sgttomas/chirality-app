**Main design choices (all PROPOSED unless marked):**

1. "Stop" is three operations (R17-3, INTEGRATION). A turn interrupt is
   `turn/interrupt` and its empty result is not the interruption: only
   `turn/completed` reports it. Nothing here ever ends a run.
2. Quit asks first with live work and has no timeout (K-4, SETTLED). On
   confirmation the App interrupts each live turn, waits a bounded time, then
   stops the supplier. Labels: "interrupted by quit", or "interrupted by quit
   (final status not observed)".
3. Requests still pending when the process stops are **not declined** by the
   App; they end *ended-unanswered(process-exit)* with their context (U-10).
4. Window loss is not observation loss for any record; only a generation end
   is (the custody schema refuses `window-closed`).
5. Re-attachment: replay from an in-memory per-generation journal; outside
   it, a snapshot plus Codex history reads with a gap marker. The journal is
   never written to disk.
6. Relaunch: read the ledger, read Codex history for each unsettled
   conversation, show Codex's status beside the App's reading, resume only on
   the person's choice, never re-send a prompt, never answer an old request.
7. The ledger holds pointers and App-observed facts only (R17-4); the schema
   refuses payloads.
8. Run ↔ thread association by opaque receiver tags, so the dependency stays
   consumer → DEL-01-02 (R17-10).
