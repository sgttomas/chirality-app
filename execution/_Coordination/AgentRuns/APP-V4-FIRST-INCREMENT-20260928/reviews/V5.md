## 5. Residuals

### MAJOR

**MAJOR-1: ADAPTER GC-5 puts every non-A5 kind (b)/(c) run halt in the
App-side class. This contradicts R6-1 and the HS-3 bullet directly above it.**

- **Where.** ADAPTER §5.3 GC-5, second bullet (l.517–523): "any held action
  is App-side (HS-5) — … an App file write or return step, **or a kind (b)/(c)
  run halt other than an A5 constraint** (GC-3 covers A5 …): **not
  enforceable** in App runs whatever SWBPIPE answers". The R6-1 change row
  (l.1083) records this as the R6-4 exception.
- **Why it is wrong.**
  - R6-1 decides by *what the checkpoint must hold*, not by arrival kind.
  - The HS-3 bullet in the same list (l.511–516), ADAPTER's own
    classification bullet (l.459–466), EXEC HS-3 ("the host operations after
    arrival until the act"), ACT `CP-L4` (kind (c), host operations only →
    HS-3), AS F6d and GUIDE §2.14 all put a kind (b)/(c) checkpoint whose
    held actions are all host operations in **HS-3** (*not established*
    today).
  - GC-5's HS-5 bullet makes the same checkpoint HS-5. EXEC evaluates HS-5
    first, so under that reading it would win (*not enforceable* →
    *unsupported*).
  - This is the V4-A MAJOR-1 contradiction, re-introduced in the file that
    consumes the values for X.
- **Effect.** No over-claim, but a conflicting and more conservative value
  for CP-L4 or F6d-shaped checkpoints on X.
- **Side to change: ADAPTER.** Replace the phrase with "or a kind (b)/(c) run
  halt whose held actions include any App-side step (a run halt holding only
  host operations is HS-3 above; GC-3 covers A5)". Correct the R6-1 change
  row to match.

**MAJOR-2: RELAY SQ-02 does not ask the host about the HS-3 case R6-1 added,
where host operations are held after arrival until the act.**

- **What changed.** R6-1 widened HS-3 beyond A5 constraints and kind (a)
  calls to "the host operations after arrival until the act". EXEC HS-3,
  ADAPTER GC-5, ACT `CP-L4`, AS F6d and GUIDE §2.14 now carry it.
- **What SQ-02 asks.** Its questions ask:
  - (a) receipt and verification of an **A5** constraint;
  - (b) a host-held declaration or run association;
  - (c) *not permitted* for a direct request;
  - (d) host holds "before dispatch of a named operation";
  - (e) evidence.

  Its answer form asks only for "a yes/no for host holds before dispatch per
  surface".
- **The gap.** Nothing asks whether the host will refuse the run's host
  operations after a kind (b)/(c) arrival until the act.
- **Effect.**
  - Suppose the owner answers (a)/(d) only. Then HS-3 (a), "a host hold
    evidenced", and HS-3 (c), "answered with no host-held route", are both
    arguable for such checkpoints.
  - The value would not be deterministic after the answer, and a second
    relay round would be needed.
  - Today's value (*not established*) is unaffected.
- **Side to change: RELAY** (SQ-02), before the owner relays it.
  - Add a sub-question (f): "When a checkpoint arrives on an observed output
    or host outcome, will your route refuse that run's further host
    operations until the act, on each surface?"
  - Add a matching slot in the answer form.
  - Add the new case to "Depends" (ACT `CP-L4`, AS F6d, ADAPTER GC-5).

**MAJOR-3: WD's *held actions* element says that A5 and kind (a) held
actions "are derivable", yet its default and its fixtures treat an absent
element as App-side even for kind (a).**

- **The text.**
  - WD §4.3.1 (held actions row): "For an A5 checkpoint it is the governed
    operation(s) and for kind (a) the held call; **both are derivable**.
    Absent this element … consumers assume at least one App-side step
    (conservative default, EXEC HS-5)."
  - WD VC-43 and WD-EX E8 row "L-WDEX-17 with its held-actions element
    absent" value a **kind (a)** `CP-grant` on OP-C9 as HS-5 → **not
    enforceable** → *unsupported*.
  - EXEC §3.6 defines the held actions of an A5 or kind (a) checkpoint as its
    governed operation, which would make that case HS-3 → **not
    established**. EXEC's own table derives `CP-accept`'s held actions "(the
    constraint forces *propose*)".
- **Effect.**
  - One declaration, two values (*not enforceable* vs *not established*), so
    two workflow results.
  - This affects every carried or legacy declaration without the new
    element. Examples are E5-style Root packages and host workflows adapted
    before R6.
- **Side to change: WD**, with the integrator choosing the reading. EXEC
  HS-5 and GUIDE §2.14 then echo it.
  - **(a)** A5 and kind (a) held actions are derived when the element is
    absent. The default applies only to kind (b)/(c). L-WDEX-17-absent
    becomes HS-3.
  - **(b)** Held actions must always be declared. "Both are derivable" is
    removed, and VC-43 stands.
