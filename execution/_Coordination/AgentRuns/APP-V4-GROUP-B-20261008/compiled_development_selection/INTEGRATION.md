## Gate and shared fence

custom-protocol nor distribution-successor implies it. All synthetic embedded
bytes/data construction require the feature and debug_assertions. Enabling the
feature for a non-debug crate is a compilation error. Ordinary default and
custom-protocol-only builds take a disabled helper without invoking its lazy
resource resolver; that no-I/O claim is scoped to this helper, not all App setup.

Only Cargo.toml feature declaration, lib.rs module/immutable AppState startup
snapshot and read-only host_status projection, new module/tests/selector,
separate opt-in package configuration/docs/tests and this evidence are in scope.

ordinary packaging config and all historical/S4 source pins remain unchanged.
No CI file change: normal CI/build commands retain feature-off behavior; the

## Physical closure and paired check

The enabled helper resolves only native resource_dir/distribution-development-reference.
Its fixed four-file closure is build-selection.s2.json, expected.json,
attestation.json and synthetic-evidence.json. The expected/attestation sources
are existing synthetic-expected.json/synthetic-attestation.json bytes; explicit
packaging destination aliases honor the attestation's existing expected.json
reference. No existing resource or record is rewritten and no fifth alias added.
The compiled selection binds exact reference/attestation bytes and their opaque
evidence. Resource mode metadata is observed only: this is artifact byte binding,
not vendor-tree mode verification or installed custody qualification.

Positive: the exact physical closure is observed through the same helper called
by actual App setup. Negative: replace reference and attestation, recompute a
consistent replacement selection, and call that path again; the unchanged
compiled bytes refuse replacement. Missing/extra/type/link resources refuse.
There is no caller digest/path parameter on the App command surface and no
fallback that turns failed physical comparison into an embedded success.

Every enabled outcome remains development-unverifiable. Startup stores one
immutable observation; host_status only reports it, explicitly not revalidated
after startup. It never changes Host readiness, configuration or admission.
The distinct opt-in unsigned debug configuration maps the closure; ordinary
package configuration neither selects the feature nor maps this resource set.
S3 acquisition/probe/trusted custody, signing, native launch and held H11/Stop
remain outside this slice. No reserved owner choice is needed to inspect this
