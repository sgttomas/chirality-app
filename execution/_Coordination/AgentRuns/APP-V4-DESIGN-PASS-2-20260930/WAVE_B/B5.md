## 1. The flow in one account (LOOP-v0.8 §5.3, DF-1…DF-10, DF-F1…DF-F12)

1. **Tool subject (DF-1).** A destination-reaching tool is a **host catalog
   entry** carrying an **external-contact declaration** (element 5: category;
   destination *fixed* or *from argument*; serving outside process). The
   agent asks through the host's **destination request entry** (entry kind;
   class none; contacts nothing), which **carries the call** that needs the
   destination. MCP tools reach the agent only as catalog entries. **No
   second tool source is needed** (LOOP G-13; C §3.4).
2. **Identity (DF-2)** is {category, destination name}: origin for web/API;
   server identity for MCP; model-choice endpoints for the model service.
   **Allow rule (DF-3)** A-1 model choice (class local/cloud) → A-2
   always-off → A-3 non-stateless MCP (not grantable) → A-4 named entry (on
   its own, K1-5) → A-5 switch on → A-6 in-work grant in force → A-7 refused.
3. **Position (DF-4):** model request; **V-D after V-3, before the kind (a)
   step and dispatch** (new row in §6); and **at contact**, where the
   contact is written before sending (F-4 fail closed).
4. **Request (DF-5, DF-6):** states *pending → granted · declined · not
   granted (not grantable · grant refused by control · prompt not shown) ·
   unanswered at end (run ended · turn cancelled)*. The request call gets an
   **interim notice** (loop state, like TL-3's held call), then at most one
   result in TL-2's four classes: the carried call's class 2/3/4 outcome;
   class 3 "granted: ‹scope›"; class 2 **"destination not allowed by the
   person"** (host control); class 2 **"destination not allowed"** (reason);
   none when unanswered. A direct call refused at V-D gets class 2
   "destination not allowed", request offered. A turn with a pending request
   waits in *awaiting destination answer*.
5. **Record and display (DF-8, DF-9):** RS R15 kinds `destination_requested`
   (with carried call), `destination_grant`, `destination_contacted` (+ model
   class), `destination_declined` and `boundary_refusal` (+ stage; recording
   PROPOSED), new `destination_request_closed`, `outside_process` (+ stateless
   evidence); R11 "stateless revision declared, not verified". **The
   contacted-destinations display is DEL-04-02's (new AS §3.2)**, per its
   ScopeOfWork CLM-002 ("…contacted-destination record, which DECISION-5
   requires to be shown"; DEP-04-02-018); PANEL ND-4 receives it as ND-5
   receives AS §3. The prompt (ND-2, PS-1…PS-6) stays PANEL's.
