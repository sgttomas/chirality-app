Steps: pre-flight without Codex (binary sha256; LM Studio server, model key,
load with a large context; `GET /v1/models`; one `POST /v1/responses` with
invented text; `lms log stream`); scratch `$TMPDIR/chirality-obs1-0.158.0`
with `codex-home` a copy of the spike's warm home (avoids the ≈24 MB plugin
fetch at start) and a neutral `cwd`; `config.toml` with a custom provider
entry to `http://127.0.0.1:1234/v1`, `wire_api = "responses"`, read-only
sandbox, `on-request` approvals, web search and analytics off, and the MCP
test double; then initialize → initialized → `mcpServerStatus/list` →
`thread/start` (checks on provider, model, `instructionSources`) → one
`turn/start` asking for `example_lookup` EX-1 (and EX-ERR) → answers by a
labelled harness → `turn/completed` → stop. Every frame, the MCP log, 250 ms
process and socket snapshots and the LM Studio log are recorded.

Risks and stops: a model download through Codex's local-provider path or
LM Studio (S-2); LM Studio not serving `/v1/responses` or no tool call from
the 9B model (P-5, S-8 → Qwen3 4B per the owner's answer); sign-in asked
(S-3); instruction files outside the scratch (S-4); non-loopback model
traffic (S-5); `~/.codex` touched (S-6); 10-minute limit with one
`turn/interrupt` (S-7); memory on 16 GB (S-9). Parts B (CLI turn), C (LOOP
Chat Completions points) and D (per-thread MCP config, no turn) need
HELP_HUMAN's decision; B is a second turn, beyond K1-6's "one turn".
