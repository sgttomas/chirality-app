## Method

1. **Inventory.** `git grep -l -e '/Users/<owner>' -e '-Users-<owner>-'` over `projects/chirality-app-v4` gave the files. Each hit was recorded by file, line and path form.
2. **Hash binding.**
   - Each file's sha256 was computed.
   - One `git grep -I -i -F` pass over the whole repository searched for every file's 8-hex prefix.
   - Each match was kept only when:
     - the hex run starts on a hex boundary;
     - the whole run (8, 12, 16 or 64 characters, or any length in between) is a prefix of that file's sha256;
     - the match is in a file other than the file itself.

   The 8-character search finds every longer prefix as well. The only matches shorter than 64 characters were two 12-character citations of `reviews/V19-B.md`. Both were checked by hand and are genuine.
3. **Structural binding.** These count as bound whether or not a hash was found:
   - `_DAG/`, including `_DAG/_Candidates/`;
   - `_ScopeChange/checkpoint_snapshots/`;
   - `_ScopeChange/SCA-*/`;
   - `_Decomposition/checkpoint_snapshots/`.

   **Manifests that list paths without hashes** (for example the `review_receipts` of `CP1_DRAFT_MANIFEST.json`) were checked separately. None lists an editable file from its own folder.
4. **Edits.** The convention was applied to the editable files only, and each file's hash was checked against the inventory before it was edited.
5. **Checks after the edits.**
   - Manifests: before/after comparison.
   - GUIDE pins.
   - DAG-004 currency.
   - JSON validity of the edited JSON file.
   - Hit recount.

**Limits of the method:**

- A binding that hashes a whole tree, or hashes transformed bytes, would not be found. The structural rules cover the known snapshot areas.
- Hash prefixes shorter than 8 hex characters were not searched.
