## Binding and selection

`binding.schema.json` defines `exp-support-binding.canonical.v1`. Each binding
contains the method version, fixed declaration SHA-256, complete EXP version /
three schema IDs / prototype SHA-256, and exact record kind, ID and byte digest.
The sidecar preserves the original record; its exact bytes are separately bound
by the selection. A result's existing support fields must agree, including its
prototype digest on this stronger route. PKG's existing version must agree;
review/change support is carried by the sidecar. Legacy field optionality is
unchanged for legacy readers.

`binding_purpose` distinguishes `current_producer_declaration` from
`historical_correspondence`. The first is the producer's declared selected basis
for the explicit new binding cohort, not verified producer history. The second
checks a historical artifact against the identified sources without asserting
it was written under them. Generating a sidecar today never upgrades a historical
artifact's provenance, result or standing. Both purposes always report actual
producer use as unverified; a claim that bytes were really written under a basis
requires its external production evidence. A writer cannot prove that fact
through a flag or digest.

`exp-support-selection.canonical.v1` freezes the method/declaration, purpose,
six artifact pairs and explicit package/review/change selections. Artifact roles
are `before`, `after`, `rerun`, `review`, `change`, `package`. Each record and
binding reference carries a relative path and exact SHA-256. The caller supplies
the previously frozen selection digest; changing any selected field requires
a newly identified technical selection, not silent following of a path.
All bindings must have the selection's purpose. The current package joins the
rerun; before/after are the same prior result before/after its currency update.
Earlier package custody and omitted history remain outside that bounded join.

## Required checks and preserved limits

The canonical reader must validate the closed canonical binding and full identity,
then call the unchanged maintained package-link, review-join and change-join
validators on the original captured record bytes. The adapter may derive internal
unpublished v1 sidecars for the existing checker; it must never alter the records
or present those derived sidecars as external authority. The report retains the
canonical input identities, existing rule results and prerequisite gaps.

Missing/different sources, altered bytes, mixed versions or purposes, forged
publication fields, missing/duplicate identities, unresolved evidence and failed
existing joins refuse. Schema validity and support correspondence do not prove
an observation, native route, independent review, repair, signing or qualification.
Filesystem link checks are best effort, not hostile concurrent-filesystem custody.

receiving supplement form this method's initial full-identity cohort. Producers
using this route freeze their selected basis and retain both original record and
