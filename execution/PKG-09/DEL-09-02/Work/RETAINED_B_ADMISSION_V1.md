## Observation and cleanup boundaries

`native_b_diagnostic.py` has no UI action, launch, image or permission-request
API. It uses the original retained Child, fresh WNOWAIT and kernel birth/UID/
parent/executable/hash before and after observation. WindowServer uses all rows,
reads owner PID first, and only decodes/retains matching rows (number, layer,
bounds, on-screen, optional title). Screen Recording is preflight-only; missing
title/access is explicit. Raw own-App AX attributes preserve return codes and
CF types for Windows/MainWindow/FocusedWindow/Children, with nonrecursive owned
role/type references and CFEqual duplicate/self-reference observations. Foreign
rows are never retained. A window never ordered in may have no WindowServer row.
The inter-call budget is eight seconds, with AX messaging timeout0.5 seconds;
WindowServer calls themselves have no cancellation guarantee. Refusal is an
unavailable diagnostic, never absence, process settlement or release authority.

The controller attempts this inventory once after distinct-window readiness or
its bounded failure, before ordinary same-source cleanup. A refusal is recorded;
no arbitrary activation/reopen variant or second launch follows. Native APIs
have not been invoked in this preparation; tests inject fake backends.

Exclusive pending now sets the stop reason without skipping census/RSS,
memguard or free-memory observations during a hold. Each observation has its
own timestamp/source/success or failure; an unsuccessful census is not relabelled
fresh by the keeper heartbeat. Independent observations continue if another
fails. Launch admission still refuses exclusive pending, resource-limit failure,
missing guard or overlapping candidate processes. No memory benchmark is added.
Administrative release remains exact-control-bound, failed qualification and
retained-Child-only; its result now also retains guard reason and sampling facts.
