source/question/settlement validators, isolated activation/capture helper and
native owned-menu Quit. The base AX primitives already execute in the keeper;
no new C reader/plugin, system-wide AX element, untrusted native library or
extra executable is introduced. Window-number bridge availability is required;
it is not assumed to be a public portability guarantee. Per-element ownership
checks precede attributes and a0.2s messaging timeout is set. String/array bounds

aggregate main text is bounded, and the journey permits at most64 main/modal reads.
Phase liveness is checked through the existing callbacks; native calls remain
non-cancellable individually, so cumulative budgets are enforced at boundaries.

Main snapshots retain actual AX properties, WebKit membership and walk notes;
source records identify native AX provenance, not screenshot transcription or
supplier-native JSON. Raw modal snapshots can be retained before a later binding
or question refusal and are not themselves accepted confirmation proof. Actual
WebKit absence, self-reference, missing/ambiguous/disabled control, wrong window,
text/parser refusal or unexpected question produces a concrete failure; no
internal command or guessed value substitutes for it. A terminal boundary failure
suppresses alternate cleanup observation. Held status exposes Stop intent/post/
confirmation facts and warns that flags do not prove modal dismissal: unsupported
question states require prompt manager escalation, not blind Quit/escape.

The existing after-slot295 seconds and phase caps remain: initial15, ready60,
recheck35, cleanup-source35, Stop20, modal30, settlement45 and40-second exit reserve
(with the existing admission allowance). Native traversal/control latency and
WebKit exposure remain unmeasured. A successful mocked journey is not evidence
that the actual UI exports the same attributes. Screenshots only corroborate;
they cannot fill missing AX source or manufacture qualification.
