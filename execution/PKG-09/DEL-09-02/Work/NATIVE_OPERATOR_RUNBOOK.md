# Bounded native operator delivery runbook

Manager owns the original Child, guard/slot and cleanup through actual closure.
A single short-context TASK may operate the current private screen-control
channel and verified own-window images only. It cannot launch, edit frozen code,
read supplier/account contents, widen capture, query other windows, change
permissions or perform recovery actions. Manager remains active and handles the
known safe menu Quit/admin release if qualification cannot establish source.

Before launch: complete ONE full offline handoff rehearsal, retain its timed
result and explicit unmeasured costs, and decide whether the existing phases fit.
A failed/uncertain fit returns method choices to Agent0 rather than incremental
patches or another launch. Fresh exact state/source/inventory/resource gates and
review of any material boundary change remain required. No budget extension.

Operator sequence under existing controls:

1. Initial acquisition/capture: inspect the current verified image. If inactive,
   request focus once; actual AXFrontmost and visible effect must be observed.
2. Ready (60s): More tools → Host diagnostics → Lifecycle and Raw envelopes;
   obtain complete displayed header/lifecycle/clientRequests/envelopes, citing
   every current-phase image needed. No expected-value filling or missing fields.
3. Recheck (35s): re-read the entire source/protocol witness in the new phase.
4. Cleanup source (35s): re-read the complete same-source witness before Stop.
5. Stop (20s): use Connection & access and the current bound Stop control once.
6. Modal (30s): only the uniquely derived owned modal; transcribe complete title,
   question and button. Confirm only exact same-source/generation zero-work effects.
7. Settlement (45s): fresh complete diagnostics, source and LT23 leader/descendant
   settlement plus protocol witness. Image/posted-event success is not settlement.
8. Normal Quit/closure reserve (40s): keeper's reviewed native menu and original
   Child checks; manager separately records actual exit, controller return and
   resource release. Failed qualification stays false after administrative cleanup.

Each coordinate is a numeric pair `point: [x, y]`, not an object. Each control is written private0600/single-link then atomically renamed to the
current prompt's path. The TASK reads an actual verified image before acting;
no prequeue, cached coordinates or cross-phase source transcription. A pending
input effect allows read-only recapture, not another input or invented success.
Changed pixels before posting mean proven-unsent reobserve; ambiguous posted
input is never repeated. Near phase expiry, refuse rather than race a late action.
No focus/transport/yield/flag/permission workaround inside a run.

The full offline rehearsal includes actual TASK/tool/image/control publication
latency plus explicit allowances:5s admission,5s initial acquisition/capture,
1s fresh phase capture,3s focus+render/capture,4s other input+pre/post capture/render,
10s final native Quit/closure. Prior retained helper timings support capture/input
as subsecond operations in those runs; these larger allowances are still
assumptions. Real layout/page count, render latency, modal and LT23 latency are
unmeasured. Fixture gates use complete invented source/protocol/settlement data,
not GUI qualification. Do not replace this accounting with transcription-only time.
