# Visible autonomy and result standing

## Purpose and Objective Traceability

Expose the autonomy the person has granted, support scoped changes during
work, and make received result standing inspectable. Connect the receiving
interface to run settings, host-origin evidence, undo and later checking so
the person can validate results to the degree the situation warrants. This
UX_UI_SLICE contributes to OBJ-005: useful autonomy with attributable human
acts, result standing and reconstructable run provenance.

The contract defines App/shared receiving work. Its existence establishes no
implemented controls, adopted operation policy, received host capability,
performed human act or professional reliance. The accepted source is a
composite: later owner directions and accepted recommendations qualify the
historical original seeds. Source keys below are repository-relative.

## Production and Verification Method — Praxeology

Start with the accepted scope and the two policy/record contracts, then
resolve affected operation-policy and placement details through their actual
owners at the separately recorded points of need. Define the host receiving
contract against those decisions, construct the justified App/shared
components, and exercise their bounded interfaces. These are the production
obligations specified by this contract; initialization does not execute them.
No wire spelling, timing threshold, classifier treatment or service topology
is selected here. [B; I; S d2/d3; A V4-ARC-20]

Bind observations to the exact delivered candidate, supplied policy, record
and host evidence. A local interface fixture establishes its own observations;
claims about a real host require the host owner's evidence. Missing inputs
remain explicit without blocking independent definition work. Tests verify
the source-grounded obligations and create no new scope. [I DEP-001; O]

- **VER-001** — Exercise the receiving interface with an identified adopted policy, person-set direct/proposal scope, a during-work scope change, an unestablished change and a declared-checkpoint case. Compare visible active scope with the actual effective grant and checkpoint evidence; retain the before/after observations for AC-001. A fixture may not decide unresolved operation policy.
- **VER-002** — Compare the displayed settings and run identity with the input/output of the App DEL-04-03 record interface for a run and a during-work change. Exercise missing/unconfirmed settings; preserve the record references and comparison proving AC-002 without creating a substitute run record authority.
- **VER-003** — Use direct-application and undo interface fixtures with identified host origins/receipts. Inspect origin and later-checking access, invoke the fixture's supplied undo route and compare displayed outcome with the host response; exercise absent route/evidence and unobserved outcome cases. Record which observations satisfy AC-003 locally and which require actual host evidence.
- **VER-004** — Supply current, historical, checked, limited, content-lapsed and missing/unobserved result evidence to the receiving components. Compare each visible standing and inspectable evidence link with the supplied source, including changed-content lapse received from the record owner; retain observations for AC-004. Do not treat a display or schema check alone as proof of an upstream act or host capability.
- **VER-005** — Exercise the act-distinction cases in AC-005, including positive faithful recording with separate human decision actor and recorder, unsupported/fabricated attribution negatives, and an independently evidenced act without a different prior act. Inspect actor/subject/evidence, displayed meaning and proposal labels against P V4-AUT-03/05, H V4-HI-25/31/33 and S d3. This receiving check supplies no new human-act permission or global reserved list.
- **VER-006** — Review OUT-002 and its implementation references against B, I and CLM-001 through CLM-005: trace each consumed policy/record/host input; resolve each REQ-007 excluded act one-for-one to its actual owner; compare each open issue's owner and point of need verbatim with the accepted/current register; inspect evidence supporting any host delivery/adoption assertion. Retain gaps and unresolved decisions for AC-006.
- **VER-007** — Inspect the delivered fixture inventory against AC-001 through AC-005 and execute the bounded mid-run autonomy/standing and undo suite against the identified receiving candidate. Record case, input identity, observed outcome and limitation references, checking coverage and truthful attribution for AC-007 without substituting fixtures for an external host witness.
