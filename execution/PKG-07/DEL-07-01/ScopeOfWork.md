# DEL-07-01 — Retained PEC receiving compatibility

## Scope

PEC is retired as an active product programme by the owner's 2026-10-09
instruction. App v4 no longer owes a PEC first-consumer adapter, qualified
provider witness, release/adoption exercise or completion of OI-022/DEP-002.
No work is blocked awaiting those inputs. The former scope is recoverable
at `archive/pre-efficiency-cleanup-2026-10-09`.

## Retained contract

Existing source, schemas and fixtures remain compatibility material, not
claims of a qualified live PEC service. If retained receiving code is used,
source identity and limitations remain inspectable; absent inputs never mean
empty work, permission or readiness. It confers no execution or human-decision
authority. Shared optional-connector behaviour remains in DEL-07-02.

## Acceptance

Retirement introduces no provider delivery requirement or successor product.
Maintenance preserves truthful absence/limitations and existing compatibility
interfaces; verify affected behaviour proportionately. Reintroducing a PEC
programme or a new provider requires a separate owner direction.
