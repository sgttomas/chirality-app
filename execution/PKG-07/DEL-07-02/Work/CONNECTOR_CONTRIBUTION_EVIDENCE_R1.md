## 1. Selected incremental lifecycle

One active CCE working set shares the existing one-payload, 1 MiB budget; it is
not a second registry. An existing prepared/in-flight account prevents admission
of CCE. CCE prevents another preparation. Neither silently cancels or evicts the
other. No account identity or lifetime slot is reserved/exposed before final
successful freeze; final freeze transfers the bounded payload into one existing
CAM lifetime identity, within the unchanged 64-identity limit. Exact serialized
size includes escaping, excerpts, artifacts and all retained metadata. Failed
preflight does not reserve/expose an identity. No implicit retry or restart.

Serial stages borrow source-owner evidence and retain only their selected
artifact and bounded proof metadata. Every new authorship mint and graph
dispatch requires current original custody. Closure cannot authorize new mint,
write or retry. Previously minted same-process observations may freeze as
historical after closure. Before graph dispatch, explicit cancellation discards
the working set; source closure instead permits answer-only/review-only final
historical recording with integration outstanding. Once dispatch starts, retain
actual or uncertain write outcome despite cancellation, source closure or save
failure. An uncertain attempt is never reclassified as no write. Do not admit a
replacement set while this unresolved outcome would be silently lost.

Closure before operation mint leaves integration null with the original attempt
and uncertainty even if later bytes match. Closure after a complete genuine
operation mint permits historical archival of that outcome. Final account
publication uses CRP and consumes its token once; uncertainty preserves the
attempt and never permits automatic publication or graph-write retry.

## 2. Recovery limit and migration boundary

Prefreeze process exit loses the transient answer/review/working-set status.
The graph may already contain an edit. Final cold-account readability does not
satisfy V4-PM-05 for the whole multistage workflow. Restart must show unavailable
prior hot custody, must not infer that no write occurred, and must not resurrect
permission or mint capability from a file. This remains a named product limit.

Before any whole-product 90% claim, assess durable alternative B or another
reviewed recovery design. A possible migration is explicit intermediate
historical checkpoints using existing bounded identities: each persisted stage
would spend a slot, preserve predecessor byte bindings and uncertainty, and
resume only by fresh source admission. It would not restore a hot grant or live
message source. This is NOT selected here: placement, checkpoint triggers,
capacity interaction, interrupted/uncertain publication and reconciliation must
be reviewed before adoption. Existing 0.5 records remain historical records;
no migration silently upgrades them or requires rewriting accepted bytes.

## 4. Required negative cases for later reviewed definitions

- Imported/cold decision, fabricated actor/role, or free-text approval cannot mint.
- A16 outcome is not silently treated as A12 direct grant; class/scope mismatch
  refuses, without attributing an unperformed human act.
- Changed scope, withdrawn/superseded control, changed selected target, preimage,
  plan, account or answer invalidates dispatch; no automatic retargeting.
- A manager selection outside owner scope refuses; absent suitable target keeps
  integration outstanding.
- Host stream source replacement, late events, response/event conflicts, duplicate
  final items and historical-only sources cannot mint fresh contribution.
- Existing prepared payload prevents CCE admission; CCE prevents competing
  preparation; exact escaped size over 1 MiB refuses before identity exposure.
- Prefreeze cancellation differs from closure and crash. Post-dispatch failure
  preserves actual/uncertain outcome; cold recovery never says nothing happened
  merely because no final account exists.
- Final cold consistency does not establish hot authority, human identity,
  acceptance or full workflow recovery.

These are definition obligations, not production or native test results. The
remaining bridge questions are routed through the manager to DEL-04-01 and
DEL-04-03; no self-concurrence or source selection is inferred.
