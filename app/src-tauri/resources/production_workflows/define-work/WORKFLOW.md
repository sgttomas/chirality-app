# Define work

Use this method when what must be done, how it fits together or how its result
will be examined needs clarification. It supports execution, assignment and
assurance; estimating and scheduling are additional uses. It can be an authorized
undertaking of its own, part of commissioning work, or a revision during execution.
If an existing brief or work definition is sufficient, use it. Do not add a
parallel definition merely to follow this method.

The result is a usable understanding of the contribution, in the representation
its consumers need: an existing brief, discussion, diagram or owning work record
may suffice. No formal Deliverable hierarchy, task count, schema or new file is
required. The work being defined can produce an understood interface, supported
judgment or resolved question as well as an artifact.

## Establish the intended contribution

Take the purpose, allowed reads/writes and authority from the assignment. Read
the governing commitments and relevant context far enough to understand the
intended recipient and use. Attribute consequential decisions and distinguish
source facts from assumptions, judgments and proposals. A source's presence or
revision label alone does not establish its authority or suitability.

Identify what a useful result would accomplish and which boundaries matter.
Expose a consequential conflict or missing basis with its affected use and
concrete alternatives; continue supported portions. Ordinary definition choices
within the assignment need no additional approval. Do not invent commitments,
appointments, quantities, prices or dates to complete a definition.

## Construct coherent work

Explain a plausible way the contribution can be accomplished from its actual
inputs. Group work into coherent functions only where doing so makes different
results, mechanisms, responsibilities or checks clearer. One function may suffice;
one can serve several outputs, and several can contribute to one result.
Include applicable inquiry, alternatives, production, checking, integration and
interaction without making every cognitive step, meeting or file a new task.
Explain consequential grouping or method choices and useful alternatives.

State what inputs must support which uses, their relevant conditions and the
interfaces that connect contributions. Keep unknown bindings explicit.
Distinguish limited preliminary use from later reliance where needed. Preserve
conditional feedback and affected rechecks instead of assuming every participant
must finish before another can begin. A statement of need does not establish
that the input is suitable or available.

Keep actual shared production and distinct receiving work understandable.
Referencing the same contribution does not create another copy of its work.
Refining a function through stages does not recreate the whole function at each
stage. Do not invent a registry, graph master or numerical planning model here.

## Make it assignable and examinable

Identify the responsible contribution, necessary collaborators, integration
route and actual decision or release authority. Separate authorship, coordination
and checking when their work differs. Unknown actual appointments stay unknown.
State the chosen approach or ordinary discretion, useful intermediate returns,
material contingencies and what must be referred to another decision owner.

Explain what would count as a useful result, which evidence or checks examine
its important claims, and who can make the relevant judgment. Distinguish author
checks from independent scrutiny where required. Completion may include stated
uncertainty only when the authorized outcome permits it.

A definition alone does not commission the production it describes. An actual
assignment selects the work and binds its actor, source context, permissions,
discretion, return and integration arrangements. These can already be present
in the same brief; there is no required separate assignment artifact.

Review of this definition asks whether it is grounded, coherent and adequate
for its intended next use. It does not perform the assurance described for
eventual work. A definition calling for independent checking has not completed
that checking, and neither an agent return nor a passing check confers acceptance.

## Inspect, return and revise

Read the definition as its contributor and receiver would use it. Check that
it covers the intended contribution, preserves boundaries and does not hide
material omissions, duplicated work or unsupported assumptions. Where useful,
frame a bounded assignment and a meaningful assurance question from it. Test a
material changed-input or failure case without expanding into an exhaustive
checklist. The [conceptual walkthroughs](resources/walkthroughs.md) illustrate
these tests; load them when an example helps.

Return or point to the usable definition, its basis and proposed or selected
standing, checks actually performed and consequential open choices. Persist
only what review, use or recovery needs. An adequate unchanged brief can be
returned by reference without a new record. Completion means a usable definition
for the selected purpose, not completion of the work it defines.

When evidence changes, inspect the affected meaning before revising. A newly
suitable input may meet an unchanged condition; an unsuitable input may leave
it unmet. Neither requires a rewritten declaration by default. Amend an owning
record only within authority and where its meaning changes; refer changes to
commitments, risk acceptance or explicit holds to their actual decision owner.
Update planning assumptions only when their modeled premise changes.

If interrupted, preserve usable partial work and distinguish prepared from
executed changes and pending checks. Resume by inspecting the actual saved state,
not by blindly replaying writes. Report unsupported portions precisely while continuing
unaffected authorized work.
