# project-setup-retained

Set up or incrementally update a project that explicitly retains the DOMAIN
route or the legacy phase and control-file route: `INITIAL` and `INCREMENTAL`
modes, phase gates, `_STATUS.md` lifecycle files, `SETUP_LOG.md`, and the
DOMAIN, semantic, estimating and scheduling dispatches.

New and current PROJECT/SOFTWARE localities use `project-setup`. Select this
package only for an explicitly retained DOMAIN or legacy project. Its
lifecycle, register, snapshot and setup-log obligations apply only where that
project has adopted them. Existing files alone do not select this route or
authorize migration.

WORKING_ITEMS coordinates this undertaking and assigns bounded contributions to
TASK. Selection does not launch setup or change roles.

## Method

1. Inspect the workspace state, infer the active phase and propose the next
   gate, as the contract's session entry describes.
2. Carry out the selected function of the retained method: initialization,
   scaffolding and drafting dispatches, scan and report, estimating, scheduling,
   or incremental setup after an accepted amendment.
3. Report a phase the method marks not provided as not provided. Do not
   reconstruct its method.
4. Stop at each confirmation gate for the human's decision, and record setup
   evidence where the project has adopted those records.

## Resources

Load [the retained contract](resources/contract.md) when framing the
assignment. Use [the retained method](resources/method.md) for the current
phase. Resolve tool commands against the selected library root.

These two resources moved here from `project-setup`. Records written before the
move name `project-setup` in `INITIAL` or `INCREMENTAL` mode; read them as
naming this package.
