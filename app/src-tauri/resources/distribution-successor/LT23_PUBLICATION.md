# Actual LT-23 publication support

The named producer extension `actual-host-lt09-lt23.s1` adds the complete actual Host LT-23 event after Stop to the existing immutable S1 publication route. The full S1 reader/schema and observation semantics are unchanged. Exact source identities remain required for receiving adoption; this document is not canonical rollout or Group B adoption.

Eligibility requires an already installed same-source LT-09 publication. The entire actual LT-23 event, full H5, start attempt, event sequence and native-held predecessor reference are captured together. Observation bytes retain their original pre-spawn phase. Association with a later event is not a terminal integrity probe, renewed installed custody, proof of zero surviving descendants, supplier qualification, or a restored capability.

Stop performs process cleanup and legacy event accounting first. One AppRuntimeCustody-owned permit serves all homes and reopened Hosts. Admission records pending before spawning one detached worker; busy, ineligible, absent-custody and spawn failure report unavailable without a queue or automatic retry. The worker uses the existing selected-source, namespace, descriptor and exact-byte readback checks. Completion or caught panic settles only the matching pending source/event; stale results cannot mutate another attempt. A later terminal sequence also prevents late LT-09 installation or errors from overriding terminal status.

No Store I/O or worker join occurs on the Stop scheduling path. Blocked filesystem work is not cancellable and may retain the single permit and namespace lease, making namespace admission retryably busy. There is no invented filesystem deadline. Closing disables jobs and installations before Exit home Stops and before session-end recording; it never joins the worker. Existing unrelated process/REC behavior is unchanged. Process abort has no completion guarantee.

A successful terminal publication is a fresh immutable single-event closure and becomes the current reference. Previously held LT-09 references remain unchanged. Failure preserves the old reference internally but exposes terminal evidence unavailable, never old LT-09 as terminal success. Stopped Host reads and an already established Runtime/native receiver retain full at-use checks. A fresh receiver first opened after Stop does not create a native view for the closed source; historical hydration remains unavailable. There is no history index, restart hydration, JSON capability reconstruction, new production issuer, S3/SEAL-2 claim, or support for other lifecycle rows.

Implementation and tests are synthetic offline behavior only. Production selection remains absent and verified standing refused. The bounded implementation basis is the reviewed LT-23 proposal SHA-256 `2c1249b64d6838a41169e470a8e64387235e49e29b0c10d860f2a1d65597364d`; source-owner concurrence and independent design review are distinct from implementation acceptance.
