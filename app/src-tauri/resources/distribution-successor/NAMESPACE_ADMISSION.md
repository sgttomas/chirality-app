# H3B-NAMESPACE-01 implementation boundary

Staged implementation of the reviewed native namespace admission contract, including CC-H3B-2-ATTACHMENT-NAMESPACE. No canonical meaning change, supplier qualification, credential act, restart hydration or release is implied. The exact reviewed proposal and technical owner/design records are retained in the h3b2_secondary author run.

Root account setup creates one live NamespaceAuthority shared by its distribution Store and attachment custody. The authority contains the immutable current complete binding plus a checked epoch; it is never serialized. Key admission preflights REC, attachment and every required Store, prepares the key resource links only within the existing explicit key action, then repeats checks against the actual complete set. Missing/error required Store is refusal, not safe omission.

Whole Store reads/publications retain a shared namespace lease and preserve their existing Store root device/inode, vendor/selection association, references and immutable artifact bytes. Old Store Arcs see the current full set. Attachment capabilities instead pin their issuing epoch: an old clone, prepared dispatch or AttachmentLink refuses new reliance after admission. Current account Store references remain readable under valid expanded geometry; old attachment capabilities do not gain that availability guarantee.

Admission uses authority.try_write, then REC writer.try_lock. Contention refuses promptly without changing admitted bindings and schedules no retry. All fallible physical/REC checks and checked epoch arithmetic precede mutation. A private prepared REC token holds the same ledger borrow through its infallible assignment, followed by authority assignment while both guards are held. Valid geometry with unavailable REC preserves protective admission separately: ledgerUnavailable=true, bindingCommitted=false, initial limit retained, no ledger created. Missing REC path or invalid geometry refuses.

Full inventory/selected closure hashing stays outside REC writer; final Store checks under writer inspect only namespace geometry and pinned root/source identities. Every later Store reliance still rechecks selected closure bytes. These are bounded filesystem observations, not an atomic snapshot. Already prepared key files can remain after failed admission; unchanged admitted bindings do not mean filesystem rollback.

Root projection and existing attachment slots install while exclusive authority is held, using field assignments only. No key Host is registered prospectively. After committed protection and Root capabilities, the new Host is constructed, receives the retained Store and current attachment capability, and only then enters the home router or starts. Later failures report protective namespace admitted; key setup unavailable. They never report original bindings retained or roll back authority. No native generation is allocated by this setup.

Attachment operation leases precede frame serialization, custody ownership locks, attachment_gate and Inner. Nested methods use the existing lease; lock_sources returns ownership tied to the lease lifetime. Dispatch retains its lease through actual pipe write and live result update, then explicitly drops it before independently leased persistence. Stop/EOF do not acquire exclusive authority; blocked IO makes admission busy, not blocked Stop. Cold resolution and the Host pointer-identity hot join share one lease, closing a cold-read/hot-overlay admission gap.

An old late persistence refusal retains actual write/response in its original Host source with an explicit unavailable durable limit. A fresh capability can read old metadata under current geometry but cannot pass the original Arc::ptr_eq hot join: it remains cold/historical, with no inferred nativeTurnRef, no replay and no prepared-as-current-nosend claim. No structural pointer substitution or automatic rebinding occurs.

Reader dependency identity additionally exposes namespaceAuthoritySourceSha256 for attachment_custody.rs. Exact App source/build joins remain required for runtime/REC/Root integration. Group B's accepted source pins are deliberately unchanged; their named independent adoption must follow the reviewed committed candidate and fresh exact-source exports.
