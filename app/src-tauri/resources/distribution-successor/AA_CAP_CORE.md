# Dormant AA-CAP original-request/event consistency core

AA-CAP records provisional consistency through a receipt position and revision. It is not authorship, role, full native-schema validity, mint, account or permission evidence. There is no production activation constructor: ordinary request callers pass no reservation. A private cfg(test) constructor supplies a single-use reservation explicitly to the selected request call, bound under Inner to its actual SourceRequest, full H5, request reference/ID, thread and captured pipe. No JSON receipt selects a capture.

The core retains fixed-capacity identities and SHA-256 digests, not request or message text. One optional slot and checked epoch under existing Inner protect one request, candidate turn, response, final item, terminal and first refusal. Early facts wait for the actual complete write and correlated response. Exact repeated parsed frames do not add facts/revisions; changed envelopes or competing final identities refuse. Closure retires the capture; actual source replacement empties it. Later conflicts revoke provisional consistency. Test readout always carries `nativeSchemaValidation=not-performed-by-core`; existing full Host handling/validation is unchanged.

## AA-CAP-PF1

Hash ASCII `chirality-aa-cap-pf1`, one zero byte, then compact JSON serialized using the locked serde_json scalar rules. Object keys sort by UTF-8 bytes; arrays retain order. No text normalization, trimming or field omission. This identifies the admitted parsed Value, not original wire lexemes or duplicate-key history. Hash collision resistance is the identity assumption. RPC ID identity is a bounded scalar digest; the actual original ID remains in the existing SourceRequest frame.

Cargo.lock SHA-256 at the selected basis: `c1910cffc3fc311fc50cae1117d5aa379dc374142c643c3b22ad85998dbf86b2`. Serializer/dependency changes require method vectors and review. No full native-schema validator is called by the core.

A borrowed preflight bounds containers to depth16,4096 total values plus object keys,128 members/elements per container,65536 UTF-8 bytes per string and256 per key. Serialization streams into a counting hash sink, accepting at most262144 bytes. A failure never returns a successful truncated-prefix digest. Retained H5/reference/thread/turn/item identities are at most256 bytes each; selected request/message text is hashed with its exact decoded UTF-8 byte length and limited to65536 bytes.

The owned Core has fixed inline capacity (measured1944 bytes on the tested arm64 build) and no owned heap containers. Sorted-key scratch uses128 borrowed entries per encoder frame, conservatively accounted across17 recursion frames:52224 bytes, plus4096 bytes reserved for traversal/sink/serializer working values, below65536 scratch. Compile-time checks guard8192 retained,65536 scratch and131072 total incremental limits. Those budgets exclude pre-existing Host parser/journal/SourceRequest allocations and compiler/runtime thread-stack overhead. Test allocation instrumentation observes successful maximum-size PF1, maximum object sorting and borrowed-input binding without heap allocation; failed serialization is measured separately. These are development ceilings, not provider suitability policy.

## Hooks and tests

Only existing Inner guards protect production core state; no new production lock or worker. Registration binds the explicit reservation to the newly created source. Existing admitted prewrite records receipt_position as dispatch_cut (never send_position). Write settlement reads the actual sender's written/error/in-progress/source-limit state and source epoch. The core follows Host protocol classification: diagnostic observation markers are not protocol facts; item/terminal notifications must have no id; responses must have id and result/error with no method. The on_line hook observes current-generation frames after receipt increment, before response correlation removal; later uncorrelated duplicate/conflicting responses remain visible. It never consumes or filters normal frames, channels, journal, REC or automatic replies.

Filtered `aa_cap` tests use anonymous CLOEXEC pipes with nonblocking writers, no child process or supplier. Small actual writes are drained with a1000ms/2048-byte acquisition bound and compared with exact outgoing bytes. Hook-fed notifications/responses are synthetic. Write-error/reported-partial controls explicitly simulate settlement and do not claim kernel partial-write evidence. Automatic replies are exercised outside reentrant hooks. Paired absent/limited/refused captures preserve ordinary client records, response channels, journal, server replies and closure output.

Pure vectors cover PF1 bounds/one-over, parsed key order/array order/Unicode/scalar encoding, retained identities/text, checked counters, late conflicts, pre-cut frames, early ambiguity and fixed retained capacity. These results do not establish full supplier-schema conformance, CCE attribution, role/WR admission or a public issuer. A later issuer remains a separate reviewed interface with its own full validation and current-source recheck.
