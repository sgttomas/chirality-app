# The 0.167.0 to 0.169.0 comparison

The JSON file inventories all definitions in both compiled bundles, including
the main bundle's v2 namespace. It records 1,805 definition entries and 100
changed or added entries; shared definitions occur in both bundles. The v2
bundle has 24 added and 26 changed definitions, with none removed. Three
separate observation findings cover recordings, delegation and the Level lane.
Each of the 103 findings has one authored disposition in the companion file.
The decisions are App Agent 0's, not the owner's.

`compare_schema.py` reads every definition, records exact JSON differences,
resolves every local reference, compares method sets and checks shared main/v2
definitions after adjusting only their reference prefix. It makes no automatic
compatibility classification and infers no relied-on subset from source
strings. The consumer files are bound by digest; the pull request and its
independent reading name the exact head at which those files are checked.
Later edits to a consumer are outside its disposition.

The old input is bound to the accepted historical files, including the record
that its generator used the npm tree rather than the archive tree. Their main
binary identities agree; whole-tree equivalence is explicitly false. The new
distribution and generation records use `same_basis.py`'s whole-record
admission primitives, with its explicit FORM_ONLY boundary retained. Stable
inputs are assumed; consistent forgery and concurrent writers are excluded.

The manifests identify every file from the stable and experimental passes.
Filename membership does not decide every method variant or nested field's
standing. The capability account resolves aggregate variants from the pinned
supplier declarations and export filters, and records the field refinements
the App uses. No supplier generator is rerun by this comparison.

Both pins' recordings were schema-validated and replies joined to their actual
requests. Their method groups and frame counts agree. Structural differences
are recorded per generation, direction and method; scalar-value equality and
concurrent event ordering are not inferred from that comparison. The authored
reading retains the separately observed interrupted history and parent/child
completion facts. ST5 used different shell settings in the two captures:
`allow_login_shell = false` and `features.shell_snapshot = false` were supplied
only at 0.169.0. The command's `-lc` versus `-c` difference is attributed to
capture configuration, and execution through a login shell is not compared by
these recordings. The new null fields are observations in these two captures,
not a general runtime claim.

The Level lane's results belong to its run tree `dc3ebfa0`, not to main or this
pin branch. Its plugin startup change belongs to PR 356, and its level table
to PR 339; the comparison records which integration must align each with the
pin. The historical evidence remains unchanged. Candidate examination is still
owed on the actual candidate.

This comparison does not establish runtime behaviour, level rows, the two
settings, contacts, lasting rules and trust, sign-in or candidate qualification;
each is shown separately. Its mechanical inventory and authored dispositions
do not substitute for the independent reading required by the pin advance.
